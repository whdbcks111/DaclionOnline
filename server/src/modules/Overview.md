# Modules Overview

`adminPanel.ts`의 플레이어 상세 snapshot은 원래 메인·서브·엘리트와 함께 `thirdJobId/thirdJobName`을 제공한다. `masterDataValidation.ts`는 3차가 정확히 하나의 1차 메인을 부모로 갖는지, 메인→3차 매핑과 지급 패시브의 직업 요구 조건이 일치하는지 검증한다.

`forging.ts`는 선택 성능 상한을 단조 세션 결과까지 보존하고, `fishing.ts`는 입질이 시작될 때 장소별 테이블에서 확정한 물고기를 미니게임 완료까지 유지해 다른 풀의 물고기로 바뀌지 않게 한다. 포획 성공 뒤에는 현재 장소와 행운으로 희귀 보물을 별도 추첨해 인벤토리 또는 바닥에 안전하게 지급한다.

`partyManager.areInSameParty()`는 내부 멤버 Map을 노출하지 않고 PVP 아군 공격을 차단하며, `getEventAudienceUserIds()`는 스킬·공격·회피 파티 피드 수신자 snapshot을 제공한다. `distributeMonsterExp()`는 기여도 분배 뒤 파티 레벨 차이와 참여자별 저레벨 일반 몬스터 감쇠를 적용하고 보스는 제외한다. `sendLocationInfo()`는 위험도 표시명과 PVP 허용 여부, 장소 태그·등록 상점·카르마 접근 조건으로 판정한 `낚시 가능`·`상점 이용 가능` 기능을 가공된 HUD snapshot으로 제공한다.

`sendLocationInfo()`의 오브젝트 행은 `entity:boss` 왕관 표시 여부와 5분을 초과해 리젠되는 보스의 기본 주기·현재 남은 시간을 선택적으로 포함하고, 현재 플레이어 기준 가능한 공격·대상·상호작용 행동만 전송한다. NPC 행은 `Location`과 `QuestBook` 공개 API로 가공한 이름·설명·퀘스트 표식을 전송한다.

Socket/HTTP 요청, 세션과 온라인 상태, 주기 작업, 도메인 객체 수명처럼 애플리케이션 수준의 조정을 담당한다.

- `serverBoot.ts`: 실제 HTTP listen 성공 시 Git 비추적 런타임 파일에 누적 부팅 횟수·마지막 부팅 ID/시각·그 시점 최신 적용 패치와 다음 patch 버전을 원자적으로 기록한다. 패치노트 작업자는 적용 완료 버전과 재부팅 전 소스 버전을 이 상태로 구분한다.
- `hudPreset.ts`: 인증 socket의 Player가 소유한 이름 있는 HUD 프리셋 목록·저장·명시적 불러오기·삭제를 중계한다. 저장과 삭제는 즉시 Player save를 기다리고 목록 요청만으로 현재 HUD를 자동 적용하지 않는다.
- `consumableBundle.ts`, `itemUse.ts`: item-use 등록기의 명시적 `quickBundle` 정책을 통과한 회복·생존·강화 아이템만 일괄 퀵 사용에 등록한다. 서버는 최대 8개의 중복 없는 정의 ID를 재검증하고, 각 아이템의 보유·요구·행동 조건과 소비 결과를 매 단계 다시 확인하며 `Inventory.useItemInstance()`를 등록 순서대로 await한다. 투척·유해 조제약, 스킬북, 초기화권, 순간이동 도구는 허용하지 않고 중복 요청은 userId 단위로 차단한다.
- `login.ts`, `socket.ts`: Socket.io 초기화·세션 쿠키 바인딩과 인메모리 세션·userId별 socket ID Set을 관리한다. 클라이언트의 `focused | visible | hidden` 상태와 최근 실제 입력 시각을 연결별로 보관하고 `getPreferredUserSocket()`으로 다중 접속 중 현재 조작 화면을 제공한다. 로그인은 IP 빈도 제한과 worker-pool PBKDF2 검증을 사용한다. 전체/채널 접속자는 다중 탭을 합친 고유 사용자 기준이며, 명시적 로그아웃은 저장 전에 토큰·socket 바인딩을 폐기하고 disconnect도 socket ID를 안전하게 해제한다. `revokeUserSessions`는 비밀번호 재설정 같은 보안 변경 뒤 모든 토큰과 연결을 폐기한다. 마지막 연결 종료는 `player.ts`의 userId keyed 10초 유예를 시작하고, 같은 세션의 재접속은 동일 Player 인스턴스를 복원한다. 명시적 로그아웃·비밀번호 재설정·서버 종료는 이 유예를 건너뛴다.
- `register.ts`, `passwordReset.ts`, `mail.ts`, `upload.ts`: 계정 등록·비밀번호 재설정·메일·프로필과 채팅 이미지 업로드. 회원가입은 소켓·만료 시각뿐 아니라 인증 코드를 발송한 정규화 이메일과 가입 이메일이 일치해야 하며 메일·확인·가입 빈도와 발급당 오답 5회를 제한한다. 가입 DB 작업은 User만 만들고, 새 쿠키로 인증된 첫 소켓 접속이 `player.ts`에서 Player와 첫 모험 튜토리얼을 생성한다. 비밀번호 재설정도 가입 이메일에 묶인 5분 코드를 사용하고 계정 존재 여부를 응답으로 공개하지 않으며, 새 PBKDF2 hash 저장 뒤 기존 세션을 모두 폐기한다. 업로드는 Multer 2.2의 파일·part·field nesting 한도와 사용자별 빈도 제한을 적용한다. 실제 단일 파일 part는 Busboy의 도달 이벤트를 Multer가 초과로 해석하는 경계를 피해 내부 `parts: 2`로 검증하며 두 번째 part는 계속 거부한다. 프로필은 512px WebP로 재인코딩하고 이전·미참조 파일을 정리하며, 채팅 이미지는 최대 1600px WebP 재인코딩, 소유권·표시 치수 snapshot API, 전체 100장·7일 보관 및 시작/매시간 정리를 제공한다.
- `chat.ts`, `channel.ts`, `message.ts`, `bot.ts`, `informationVisibility.ts`: 채팅 room, 히스토리, `/명령` 및 슬래시 없는 별칭 입력의 라우팅과 출력. 명령 인자는 단어, 명령당 하나의 자유 텍스트, 공백 포함 후보 여러 개를 역추적해 등록값만 허용하는 `list` 타입을 지원한다. `getCommandListFiltered(permission)`은 권한에 맞는 명령과 복사된 aliases snapshot을 제공하고 `subscribeCommandExecutions()`는 버튼·별칭을 canonical 명령 실행 이벤트로 노출한다. 일반 조작 명령 입력은 기본적으로 본인 전용이며 `showCommandUse: 'show'`를 명시한 명령만 공개 채널에 남긴다. 개인 채널 공개·본인 필터 기록의 통합 최근 삭제, 관리자 현재 일반 채널 공개 기록 삭제, 사용자별 히스토리 재동기화와 서버 기록을 보존하는 화면 전용 청소 API를 제공한다. CHAT/COMMAND 행동 제한, 최대 10장 묶음 이미지 전송, 현재 공개 히스토리에서 서버가 원문을 재검증하고 요약하는 텍스트·이미지 답장, 온라인 닉네임 `@` 자동완성과 회색 귓속말, 채널·근처·파티·30초 제한 광고·권한 10 공지의 서버 검증 audience, 공개하지 않는 일반 문장 SkillBook trigger, 이미지 노드를 포함할 수 있는 본인 전용 플레이어 표시 메시지와 `[파티]` 스킬·전투 필터 피드, 위치 전투 예고를 private 표식 없이 지정 사용자 히스토리에 남기는 봇 메시지 API, 정보성 명령 공개/비공개 모드를 담당한다. 필터 메시지는 `replyable: false`로 비공개 원문 유출을 막고, 플레이어 메시지를 히스토리에 넣기 직전 온라인 Player의 누적 플레이 24시간 미만 여부·악명 여부·장착 칭호를 snapshot해 `newcomer/karmaMarked/equippedTitle` 표시를 붙인다.
- 명령 오류 경계: `bot.ts`는 인자 해석과 handler의 동기 예외·비동기 Promise 거부를 모두 기록하고 5초 알림과 본인 전용 안내를 보낸다. 실행 이벤트 구독자의 동기·비동기 오류도 개별 격리하며, 오류를 Socket 이벤트 경계 밖으로 전파하지 않아 단일 명령 데이터 오류가 서버 프로세스를 종료하지 않는다.
- `karma.ts`: `combat:pvp_kill`을 구독해 일반 플레이어 처치를 지역별 Player 카르마 변경 API로, 카르마 100 이상 현상 대상 처치를 `hero` 경험치 상태효과와 개인 알림으로 연결한다.
- `tutorial.ts`: 새 Player의 `첫 모험 안내`를 시작하고 PlayerProgress의 상태·단계·완료 콘텐츠·일회성 보상 플래그를 공개 API로 관리한다. 단계 완료 뒤 다음 길이 0 notification과 버튼 없는 명령 안내 카드를 scheduler로 1초 늦춰 출력하며, 사용자별 task 교체와 현재 Player·단계 재검사로 지난 안내가 뒤늦게 나오지 않게 한다. 조회 단계는 직접 입력한 canonical 명령을, 이동·대화·상호작용·장착·사용·대상·공격·스킬·스탯은 성공 후 `GameEvent`와 지정 목적지를 검사한다. 광장→물빛 연못 상점→광장→바람결 초원 훈련 목인의 실제 동선, 지원품과 강타 지급, 실제 한 레벨 경험치를 주는 기본 조작 실습, 콘텐츠 목적지의 튜토리얼 방문 처리와 물고기 획득·광석 파괴·몬스터 처치 기반 체험 완료, 재접속 복원을 담당한다.
- `playerRegistry.ts`, `player.ts`, `party.ts`, `trade.ts`, `location.ts`, `navigation.ts`, `game.ts`, `coroutine.ts`, `scheduler.ts`: 온라인 Player와 고유번호/닉네임 목적형 조회·prefix 검색, 최대 5명 런타임 파티·60초 초대·파티 HUD, claim 스냅샷 내 양수 기여·온라인·동일 장소·생존 인원의 몬스터 경험치 공유와 다음 사망 판정까지의 처치 경험치 보호, QuestBook이 추가 처치 기여자를 검증하는 온라인 객체 조회, 같은 장소 두 플레이어의 30초 거래 요청·10분 인메모리 에스크로·양쪽 확인 교환·이벤트 snapshot, 현재 Entity 보호막 구간과 표시 가능한 스킬 쿨다운이 포함된 0.5초 Player/Location HUD payload, Player/Progress/SkillBook/상태효과 snapshot 수명·dirty 저장, 통합 Location 오브젝트/NPC ID 검증·JSON 저장, 월드 프레임/제작 대기 실행을 담당한다. `party.ts`는 첫 유효 인원에게 기준 경험치를 두고 이후 한 명이 늘 때마다 20%를 추가한 정수 풀을 20% 균등·80% 기여 몫으로 나누며, Hamilton 우선순위 `소수 나머지 내림차순 → 기여도 내림차순 → userId 오름차순`으로 남은 정수를 배정한 뒤 레벨 차이와 개인 경험치 배율을 적용한다. `navigation.ts`는 단일 이동과 A* 자동이동의 사용자별 세션·진행 알림·공통 취소를 소유하며 방문한 공개 장소와 현재 열린 연결만 통과한다. scheduler는 스킬·무기·아이템 효과가 재사용하는 key 교체/취소/반복 지연 API이며 미니게임 만료와 낚시 타이머가 사용한다. `player.ts`의 인접 위치 snapshot은 `Location.getAvailableConnections(player)`를 사용해 hidden을 제외하고 visible/locked 상태를 전송한다. 마지막 연결 종료는 Player를 registry와 월드에서 즉시 숨기고 낚시·해당 연결의 미니게임·이동·거래·제작·NPC 대화·질문 퍼즐·시전·보호막·전투 한정 효과를 정리한다. party 이탈과 최종 저장은 10초 유예 만료 또는 명시적 unload에서 수행한다. 거래 중에는 제거된 에스크로를 정기 저장하지 않고 완료 시 양쪽을 즉시 저장하며, 취소·이탈 시 원상 복구한 뒤 기존 dirty flush를 사용한다.
- `party.ts` 실제 막타 fallback: 정상 현장 기여자가 없을 때만 `actualLethalUserId`의 온라인·생존 Player 한 명에게 솔로 풀을 지급한다. 독·출혈 source가 다른 장소로 이동해도 인정하지만 현장 기여자가 있으면 추가하지 않으며, 실제 막타가 없는 경로만 기존 claim 안 마지막 공격자 fallback을 사용한다.
- `ranking.ts`: `Player.getPersistedRankingSnapshots`의 가공된 DTO를 10초 캐시하고 온라인 Player의 현재 공개 API snapshot으로 덮어쓴 뒤, 공개 플레이어끼리 값 내림차순 공동 순위를 계산한다. 비공개 플레이어는 실제 값·순위를 결과 DTO에서 제거하고 숨긴 값과 무관한 userId 순서의 별도 목록으로 반환한다.
- `stateSync.ts`: `playerStats/locationInfo`의 내용 변경 시에만 revision을 올리고 socket별 전달 stamp를 비교해 완전한 snapshot을 전송한다. `syncId`가 바뀌면 낮은 revision도 새 stream으로 인정해 재접속·다중 탭의 부분 병합 오류를 피한다.
- `player.ts` 적응형 음악 계약: Player의 실제 교전 기반 `musicCombatState`와 현재 Location의 검증된 선택 `mapColor`를 기존 revisioned `playerStats/locationInfo` 완전 snapshot에 포함한다. 수동 target과 raw Location 태그는 클라이언트 판정에 사용하지 않는다.
- `player.ts`의 HUD snapshot은 `level/exp/maxExp`, 장착 칭호, 공격 cooldown과 자동공격 모드, 현재 대상의 가공된 HP/MP/보호막/상태이상을 포함하며 위치 플레이어 목록과 PVP 대상을 실제 socket 연결 상태로 다시 거른다. 몬스터 대상은 `Inspection`의 감각 100/125/150 단계 DTO만 추가한다. 마지막 연결이 끊긴 Player는 즉시 registry에서 제거한 뒤 별도 grace Map에 최대 10초 보존하며, 재접속 시 오프라인 경과를 상태효과에 반영하고 동일 객체를 다시 등록한다. 유예 중 Player는 `isWorldActive=false`라 공격·AI 위협 후보가 될 수 없지만 기존 처치 기여는 유지한다.
- `masterDataValidation.ts`: 연금술 조제약·정제수와 조합식 data bootstrap을 포함한 아이템·스킬·직업·몬스터·자원·제작·퀘스트·NPC·장소 공개 레지스트리를 사용해 참조와 필수 아이콘 파일을 검증한다. `validateAlchemyMasterData()`는 재료·결과 아이템·상태효과, 양수 재료 수량과 결과 조제약 사용 handler를 별도 `alchemy` scope로 검사한다.
- `itemUse.ts`: 아이템 효과 handler 레지스트리.
- `mailbox.ts`: 시스템 전용 우편 발송과 20통 목록·읽기·첨부 수령·완료 정리를 제공한다. 첨부는 version 1 `ItemSnapshot[]` JSON으로 검증하고 같은 수신자의 claim을 직렬화한 뒤 Player dirty 상태를 먼저 저장한다. `claimedAt` 조건부 갱신과 Item 행 생성을 하나의 Prisma transaction으로 확정하고 commit 뒤 Inventory에 DB id 행을 Clean으로 흡수한다. 전체 수령은 실제 생성 행 수로 한 번에 20통/100행 예산을 차감한다. 단일 `sendSystemMail()`의 `sourceKey`는 소문자 ASCII 안전 규격과 `(recipientId, sourceKey)` unique tombstone으로 동일 보상 재시도를 막고 일반 우편은 정리 시 삭제한다. 대량 공개 API `sendSystemMailToRecipients()`는 지정 Player ID를 정렬·중복 제거하고 존재를 확인하며 `sendSystemMailToAllPlayers()`는 `User`가 아닌 오프라인 포함 전체 `Player` 행을 조회한다. 두 API는 payload를 한 번 정규화하고 100명 `createMany` 청크 전체를 하나의 interactive transaction으로 commit/rollback하며 0명은 생성 없는 no-op이다. 권한 10 `/우편발송 <유저ID|me|online|all>`은 정확한 소문자 예약어와 `me` → `online` → `all` → 중복 제거한 온라인 ID 자동완성을 제공하고, `online` 실행 시점 snapshot을 대상 API에 넘긴다. 관리자 대량 payload에는 `sourceKey`가 없어 반복은 새 우편이며 결과 수신자 수는 관리자에게만 표시한다. 플레이어 간 발송과 골드 첨부는 제공하지 않는다.
- `skillBreakthrough.ts`: 보유 액티브·패시브 스킬 입력과 돌파 상한을 SkillBook 목적형 API로 검사하고, 숙련의 정수 10개 소비와 최대 레벨 +1을 `GameAction` rollback 경계에서 함께 확정한다. 성공 직후 Player 저장을 요청하며 즉시 저장 실패는 dirty 재시도로 남긴 채 이미 확정된 돌파를 성공으로 반환한다.
- `codex.ts`: 확정 몬스터/보스 처치·광맥 파괴·장소 도착·음식/생선 요리 제작 이벤트를 최종 `attackOwner` Player의 CodexBook에 연결한다. 로그인 시 `getVisitedLocationIds`만 탐험 counter 0→1로 소급하고, `codex:{category}` source를 제거한 뒤 최고 영구 rank의 누적 multiplier 하나만 다시 적용해 progress 변경·재로그인에도 중복되지 않게 한다. 신규 rank는 영구 flag가 처음 생긴 기록에서만 한 메시지와 notification으로 알린다.
- `itemAttack.ts`: `basicAttackOverride` key→함수 레지스트리와 탄약/무탄약 투사체 기본 공격 실행. `false` 반환은 직접 근접 공격 폴백을 뜻한다. 일반 물리 화살은 과거 단조 metadata를 포함해 탄약의 `property:*` 재료 태그를 공격 속성에서 제외하고, 투사체 적중 뒤에도 발사 무기의 마스터/인스턴스 적중 효과를 같은 성공 피해 조건으로 실행한다. `burst_firearm`은 긴 공격 주기의 회피 불가 3점사를 시간차 투사체 세 개로 생성한다.
- `minigame.ts`, `minigamePresets.ts`: 사용자별 단일 일회성 session/token/만료 상태를 현재 focused 연결 하나에 배정하고, 배정 socket 준비·서버 수신 시각 기반 실시간 축·action trace, 타입별 서버 validator·완료/취소 callback과 관리자용 보상 없는 낚시/일반 회피/수정 연쇄 낙석/지핵 공명 폭주/성계 교차포화/기초·고속 단조 프리셋을 관리한다. `subscribeMiniGameStarted()`는 미니게임 내부 Map을 노출하지 않고 다른 기능의 준비 상태를 정리하는 시작 이벤트만 제공한다. 최초 `ready`의 선택적 `onReady`는 소유 기능이 비용을 동기·원자적으로 한 번만 확정하며 실패/예외면 실행 시계를 시작하지 않고 취소한다. 낚시는 matching socket의 version 1 proof를 160KiB·입력/궤적 상한·유한 수치·단조 시각으로 검증하고 서버 발급 config/seed로 입력과 checkpoint를 재생해 즉시 확정한다. 가마솥 추적은 focused socket에서 최초 목표 원 안을 pointerdown한 `ready`부터 실행 시계와 만료를 다시 잡고, 그 전의 30초 idle 만료는 실패 보상 없이 `onCancelled`로 끝낸다. proof의 첫 dragging 좌표도 t=0 목표 반경 안인지 재검사한다. 절대 pointer 입력과 100ms 목표·pointer·게이지 proof를 160KiB·수치·시각·경로·seed config로 느슨하게 재생하며 성공 여부와 목표 유지율 70%·중심 정밀도 30%의 합성값을 권위 `score`로 완료 callback에 전달한다. 서버 시계보다 앞선 proof는 ready 왕복 지연 500ms까지만, 늦은 도착은 5초까지 비대칭 허용해 미래 궤적 조기 제출을 막는다. 잘못된 matching proof도 세션을 소비한다. 위험 회피·단조는 기존 서버 trace 권위와 250ms 완료 여유를 유지한다. 입력 socket disconnect·시간초과·조기 확정은 실패 callback을 실행한다. 회피 조작 속도는 대상 Player의 `speed`를 보드 이동량으로 변환하고 단조는 서버 beat 시각과 서버 수신 strike로 정확도·콤보를 재현한다. `data/bossPatterns.ts`는 같은 회피 validator를 실제 보스 3종의 주기 패턴·실패 피해·수정 보호 기믹에 연결한다. `fishing.ts`는 낚시 가능 장소·주손 낚싯대를 시작과 결과 양쪽에서 검사하고, 보조 미끼가 없으면 인벤토리 묶음을 자동 장착해 한 개만 소비한 뒤 남은 시간을 숨긴 입질 timer, 1초 입질 경고, 행운 등급, proof 검증 미니게임, 현재 플레이어 레벨의 일반 동급 사냥 경험치에 희귀도 배율을 적용한 보상, 최초 어종 도감·단계 보상, 행운 상한형 희귀 보물과 성공 시 `fishing:fish_caught` 이벤트를 연결한다.
- `alchemy.ts`: `canUseAlchemy()`가 현재 연금술사 직업과 `가마솥 연성` 보유를 함께 검사해 조제·조합표·재료 정보의 단일 권한 경계를 제공하고, 관리자 직업 변경 뒤 남은 과거 스킬만으로 조제하는 권한 누수를 막는다. 사용자별 인메모리 준비 draft는 병 수·전달 방식·1~5종 재료를 소유하고 외부에는 불변 snapshot과 열기·증감·시작·취소 API만 공개한다. TTL 만료·장소 이동·로그아웃·다른 미니게임 시작 충돌에서 정리하며, 성공한 시작은 draft를 제거해 중복 클릭을 막는다. 선택 단계에는 재료를 예약하지 않고 시작 시 보유량만 선검증하며, 최초 목표 pointer `ready`의 `onReady`에서 재료와 병당 정제수 물병을 `replaceSelectedItems(..., [])`로 한 번만 원자 소비한 직후 사용 reagent의 PlayerProgress 실험 flag를 남긴다. 시작 전 취소에는 기록하지 않고 이후 성공·실패·연결 종료에도 비용과 기록을 되돌리지 않는다. 조제는 재료·조합식 hash 기반 5종 가마솥 경로를 사용한다. 성공 결과는 `addItemSnapshot`, 중량 초과 시 현재 Location 바닥 드롭으로 보존한다. 완성약은 `resolveAlchemyPotionUse`가 formula registry와 실패약 원재료 signature에서 재구성한 canonical 효과만 실행하고, 음용은 자신에게 적용하며 투척은 현재 대상 중심으로 같은 장소의 생존 파티원 또는 공격 가능한 몬스터만 최대 2~5명까지 다시 검증한다. 독성 공격약만 독 상성 태그를 사용하고, 불안정 실패약은 속성 없는 마법 피해로 분리한다. 중심 투척 공격은 치명타·주무기 내구도·적중 효과 비활성 옵션을 사용하며 보조 범위와 자기 음용은 같은 효과원의 직접 피해로 처리한다.
- `humanVerification.ts`: 서버가 확정한 몬스터 처치의 장시간 동선 반복·간격 규칙성을 분석하고 난수 지연 뒤 사람 확인을 요구한다. required/실패 Progress와 source-key 행동 제한·피해 보호를 사용하며, 정답은 서버에만 둔 일회성 raster PNG 문제를 발급하고 Player load/unload에서 재접속 복원·정리를 담당한다.
- `forging.ts`: `career:blacksmith` 정식 메인/서브/계보 조회와 구형 독립 flag의 비파괴 슬롯 이전, 가용 슬롯 전직 API, 대장장이 직업 또는 `metal_forging` 보유를 허용하는 공용 단조 권한과 보유 스킬별 형태 조회 API를 제공한다. 제련 소재 선검증은 마나 수정 원석과 정제 소재를 구분해 필요한 제련 절차를 안내한다. 재료 power·형태 크기로 정박/엇박/연속박자를 확정하는 config, 45% 이후에도 점감 성장하는 제련 정밀도 서버 판정, 어려운 패턴 품질 보정, 실패 소재 파손/성공 snapshot 교환·이벤트를 연결한다. 완성품에는 고정 상한에서 잘리지 않는 제작자 레벨·감각·제련 정밀도 숙련과 장비 레벨을 전달하고, 양호 품질 기준 동레벨 일반 사냥의 80%가 되도록 경험치를 계산한다.
- `adminPanel.ts`: 권한 10 세션을 재검증하고 온라인 우선 플레이어 목록·카르마 단계·보유/장착 칭호·사람 확인 상태가 포함된 가공 상세 snapshot과 칭호를 포함한 마스터 option을 제공한다. 카르마 설정, 단순 레벨 설정과 성장 지급분을 동반하는 `Player.adjustLevel` 조정, 인벤토리/보유 스킬 레벨·칭호 부여/회수·직업/상한 없는 상태효과 레벨·사람 확인 실행/해제·월드 운영과 전체 채팅·전체 알림·선택 온라인 플레이어 알림 action을 소유 도메인 API로 실행한다. 전투 프로파일은 양쪽 HP, 실제 누적 피해 처치 시각, 최대 단발·첫 반격 전 폭딜, 양방향 회피, 보스 기술과 무회피/회피/방어기 포함 생존을 가공 텍스트로 반환한다. 액션 결과는 요청 소켓의 기본 notification으로 피드백한다.
- `playerRegistry.ts`의 온라인 신원 snapshot은 레벨 순위 공개 설정을 적용해 비공개 플레이어의 `level`을 생략한다. 귓속말 mention과 파티 초대 자동완성은 이 가공 DTO를 재사용한다. `login.ts`는 `nicknameChangedAt` 기준 일반 계정 24시간 닉네임 변경 제한과 권한 10 이상 예외를 소유한다.
- `location.ts`/`game.ts`는 JSON 장소에 `ascendantRegions`의 생성 권역을 ID 기준으로 합친 뒤 온라인 Player snapshot을 Location tick에 전달한다. 같은 snapshot으로 `location:boss_room`의 살아 있는 보스 선공과 권역별 환경 passive를 처리한다.
