# 이벤트·진행 상태·스킬 시스템

## 구성과 데이터 흐름

```text
Entity/Resource/SkillBook
  └─ emitGameEvent(id, actor, subject, data)
       ├─ 최근 500개 GameEventTrace (메모리, 원시 Entity 미포함)
       └─ defineStatistic subscriber
            └─ PlayerProgress counter/flag/state (메모리 + dirty)
                 └─ SkillBook 자동 획득 검사

일반 채팅 / 명령어 / 자동 조건
  └─ SkillBook.activate*
       └─ canUse/canActivate → onStart → onUpdate → onFinish
```

`GameEvent`는 도메인 동작을 직접 DB나 스킬에 결합하지 않는 동기식 내부 이벤트다. handler에서는 DB I/O를 하지 않고 Player가 소유한 메모리 상태만 변경한다. 운영 진단용 trace는 최근 500개만 유지하며 `getRecentGameEvents()`가 ID·사용자 ID·이름·primitive data 스냅샷만 반환한다. 프로세스를 재시작하면 trace는 사라진다.

현재 표준 이벤트 ID는 장소 도착, 치명타, 공격 적중·회피, 대상 지정, Entity 제압, Resource 파괴·성공 상호작용, 아이템 장착·성공 사용, 낚시 성공, 스탯 분배, 스킬 획득·시작·종료, 제작법 발견·아이템 제작, NPC 대화, 상태효과, 퀘스트, 직업 배정·엘리트 전직, 칭호 획득·장착·회수다. 새 이벤트는 `GameEventIds`에 넣고 실제 상태가 확정되는 모델 API에서 `emitGameEvent()`를 호출한다. 명령 호출 자체는 성공 증거로 사용하지 않는다. 퀘스트 목표 추적은 [퀘스트 시스템](quests.md), 칭호 획득과 장착 패시브는 [칭호 시스템](titles.md), 종별 기록과 영구 보너스는 [전문 도감 시스템](codex.md)을 참고한다.

## 진행 상태와 통계

`PlayerProgress`는 다른 기능과 NPC 대화 조건에서도 재사용하는 플레이어별 범용 상태 저장소다. 값의 종류는 클래스형 enum `ProgressType`으로 구분한다.

칭호는 별도 테이블을 만들지 않고 `title-owned:*` 소유 FLAG, `title-blocked:*` 관리자 회수 FLAG와 `title:equipped` STATE를 사용한다. 칭호 콘텐츠와 관리자 도구는 Progress 원본 Map이나 DB row를 참조하지 않고 `PlayerProgress` 조회 API와 `TitleBook` 명령형 API만 사용한다.

| 종류 | 공개 API | 용도 |
| --- | --- | --- |
| `COUNTER` | `getCounter/setCounter/increment` | 처치·치명타·수집 누적값 |
| `FLAG` | `getFlag/setFlag` | NPC 첫 대화, 퀘스트 완료 같은 영속 bool |
| `STATE` | `getState/setState` | NPC 관계 단계, 분기 상태 같은 짧은 문자열 |

모든 key는 `namespace:path` 형식이고 사용 전에 `defineProgress()` 또는 `defineStatistic()`으로 등록한다. 다른 기능은 내부 Map이나 Prisma row를 참조하지 않고 위 목적형 API와 `getSnapshots()`, `subscribeChanges()`만 사용한다. 기본값인 `0/false/빈 문자열`은 DB row를 만들지 않는다.

`defineStatistic()`은 하나의 게임 이벤트를 구독하고 최종 `attackOwner`가 Player일 때 해당 counter를 증가시킨다. `combat:critical_hits`와 14종 속성 몬스터 처치 횟수가 공개 통계로 등록되어 `/통계`에 표시된다. 불·얼음·전기는 자동 주문 해금과 저장 호환을 위해 기존 `career:mage_*_kills` ID를 유지하고, 물·자연·독·돌·어둠·빛·언데드·신성·벌레·금속·땅은 `combat:property_kills/{key}` ID를 사용한다. 처치 통계는 권위적 `combat:entity_defeated` 이벤트의 subject가 실제 몬스터이면서 해당 `property:*` 태그를 가질 때만 증가하며 `/속성표`의 기존 표시명과 아이콘을 재사용한다.

전문 도감은 총합 통계를 종별 기록으로 추측하지 않고 `codex-entry:*` counter와 `codex-rank:*` 영구 flag를 별도로 사용한다. `CodexBook`이 진행·분류 점수·10%/35%/70% rank 해금을 소유하고 `modules/codex.ts`가 확정 처치·광맥 파괴·장소 도착·요리 제작 이벤트만 연결한다. 기존 `world:visited/*` flag는 로그인 시 탐험 엔트리 0→1 소급의 유일한 원본이다. 기존 `FishingCollection`과 `/낚시도감`은 이 registry에 합치지 않는다.

성공한 공격은 `combat:attack_hit` 이벤트에 직렬화 가능한 `weaponType`과 최종 피해량을 담는다. 검·도끼·활·단검·지팡이 적중 통계는 숨김 counter로 누적되며 각 200회에 해당 무기 숙련 패시브를 자동 획득한다. 숙련 효과는 올바른 주무기를 장착한 동안에만 적용되고, 투사체 공격은 최종 `attackOwner`의 장착 무기를 기준으로 분류한다. 활 숙련은 공격력 4%와 치명타율 3%p를 함께 올려 검 숙련으로 갈아타는 편이 유리해지지 않게 한다.

제작법 발견은 새 테이블을 추가하지 않고 `crafting:recipe/{namespace}/{path}` 형식의 숨김 FLAG를 사용한다. 정의와 자동 발견 흐름은 [crafting.md](crafting.md)를 참고한다.

대장장이는 `career:blacksmith` 정식 1차 직업으로 메인/서브 Progress STATE 중 하나에 저장된다. 구형 `profession:blacksmith` FLAG 정의는 기존 보유자를 빈 슬롯으로 자동 이전하기 위한 숨은 호환 값이며 신규 획득에는 사용하지 않는다. 마력 제련은 대장장이 계보 조건을, 단조 명령은 대장장이 계보 또는 별도 `금속 단조` 스킬 보유 여부를 공개 API로 확인한다. `야전 수리`는 대장장이 전직 시 지급되는 5레벨 생활 스킬이며 성공한 `/수리`에서만 경험치를 얻는다. 수리에는 원 단조 소재를 우선해 1~2개를 쓰고, 없으면 장비와 같은 `material:*` 또는 `property:*` 태그의 비장비 소재를 사용한다. 손상률 25%까지는 최대 내구도를 보존하며 이후 50%/75% 경계에 따라 최대 내구도 열화가 2%/6%/12%로 커진다.

NPC 조건부 진입과 대화 결과도 같은 flag/state API를 사용한다. 현재 `npc:monster-hunt-question` 숨김 FLAG가 안내인 대화 분기에 쓰이며 자세한 흐름은 [NPC·대화 시스템](npc-dialogue.md)을 참고한다.

## 스킬 정의와 인스턴스

`data/skills.ts`의 `defineSkill()`이 코드 마스터 데이터를 등록하고, Player별 `Skill`은 레벨·경험치·쿨다운 종료 시각·획득 정보·영속 태그·metadata delta만 가진다. `SkillBook`이 보유 목록과 수명주기, 자동 획득·자동 발동, dirty 저장을 소유한다. `SkillContext.owner`는 실제 시전자 Entity이며 `player`는 플레이어 시전자일 때만 존재하므로 같은 `SkillData`를 Monster도 실행할 수 있다. `SkillBook.createRuntime()`은 몬스터 수명 동안만 유지되는 비영속 스킬북을 만든다.

스킬의 실제 최대 레벨은 마스터 `SkillData.maxLevel`에 인스턴스 delta의 `progression.maxLevelBonus`를 더해 계산한다. 액티브는 누적 +5, `skill:passive` 패시브는 누적 +2까지만 돌파할 수 있으며 저장값이 음수·소수·비정상 범위여도 로드 시 정수 범위로 안전하게 정규화한다. metadata를 먼저 복원한 뒤 동적 상한으로 레벨과 경험치를 정규화하므로 기존 최대 레벨 스킬이 돌파된 뒤 쌓은 경험치도 재접속에서 유지된다. 상한만 올릴 때 현재 레벨은 바뀌지 않고 이후 정상적인 스킬 경험치 획득으로 원래 마스터 상한을 넘어 성장한다.

`/스킬돌파 <보유 스킬 이름>`(`숙련돌파`, `skillbreak`)는 패시브와 현재 숨김 상태를 포함한 보유 스킬을 `SkillBook.findOwnedByInput()`으로 찾고, 숙련의 정수 10개를 소비해 최대 레벨을 1 높인다. 자동완성은 `getMaxLevelBreakthroughSnapshots()`의 돌파 가능 스킬과 현재/누적 상한만 사용한다. `performSkillBreakthrough()`는 재료 소비와 `increaseMaxLevel()`을 동기식 rollback 경계로 묶어 스킬 상태가 바뀌면 정수를 복구하고, 성공 직후 `Player.save()`를 요청한다. 즉시 저장이 실패해도 이미 확정된 돌파를 실패로 안내하지 않으며 남은 dirty 상태를 정기 저장에서 재시도한다.

Lv.400 이상 `MonsterRank.BOSS`는 등록 경계에서 `숙련의 정수` 1개 확정 드롭을 정확히 하나 갖도록 정규화된다. 기존 위협도 우선·마지막 공격 owner 전리품 귀속은 그대로 사용하므로 고레벨 보스 반복 처치가 선택형 스킬 상한 성장의 공급 루프가 된다.

`SkillData`의 확장 지점은 다음과 같다.

- 표시: `icon`, `descriptionTemplate`, `costTemplate`, `activationConditionTemplate`, `isVisible`.
- 계산: `baseMetadata`, `calculatedFields`, `calculateMaxCooldown`, 태그별 `sharedCooldowns`, `calculateExperienceGain`, `calculateRequiredExperience`.
- 밸런스 진단: `balance.role`, 실제 발동식과 공유하는 피해·소모·회복·보호막·지속 버프 callback, 직접 피해 속성, 치명타 방식·타격/대상 수, 스킬 고유 관통 계산과 회피 불가 여부.
- 획득/발동: `autoAcquire`, `autoActivate`, `activateOnMessage`, `canUse`, `canActivate`.
- 수명주기: `onAcquire`, `onStart`, `onUpdate`, `onFinish`, `onPassiveUpdate`, `onPassiveInactive`.
- 분류: `tags`, `maxLevel`, 권장 자동 획득·프로파일 시점인 `unlockLevel`, `aliases`, `activationMessage`, 선택적 `activationHeader`.
- 직업/장비: `jobRequirement`, 선택적 `weaponRequirement`, 공통 메시지 시전어 `activationPhrase`.

`activationPhrase`가 없으면 `activationMessage`를 일반 채팅의 정확 일치 시전어로도 사용한다. 직업 요구 조건은 [직업·전직 시스템](careers.md)의 `CareerProfile.hasJob`을 사용해 엘리트 하위 계보를 자동 호환한다.

`weaponRequirement`는 검으로 베기, 활로 사격하기처럼 장착 무기 자체가 기술 동작에 필요한 경우에만 둔다. 주문·자체 생성 투사체·마도 장치처럼 스킬이 효과 매개체를 직접 만드는 경우에는 무기 조건을 두지 않으며 주무기 내구도도 소모하지 않는다. 지팡이는 마법력과 투사체 가속을 높이고 마법 기본 공격을 제공하는 선택 장비이지, 마법사 스킬의 시전 자격이 아니다.

스킬 템플릿은 `{{icon.atk}}`, `{{icon.magicForce}}`, `{{icon.projectileAcceleration}}`처럼 `icon.{AttributeKey}`를 사용하면 해당 `AttributeType.iconMarkup`으로 치환된다. 공격력·마법력 계수, 관통, 방어, 속도, 투사체 가속, 치명타와 정신력 소모 표기는 이 문법을 사용해 상태창과 같은 대표색 아이콘을 재사용한다.

투사체 스킬 정보는 현재 능력치로 계산한 도달 시간을 표시한다. 모든 투사체는 owner의 `projectileAcceleration`을 마스터 데이터 계수만큼 반영하며, 마법 피해 투사체 스킬은 여기에 스킬 레벨당 8%와 마법력 1당 0.2%(마법력 기여 최대 75%)의 가속 배율을 추가한다. 표시 tooltip과 실제 발사는 `calculateProjectileAcceleration/calculateProjectileTravelTime`을 공유한다. 계수 적용이 끝난 가속은 `calculateProjectileEvasionSpeed`로 회피 판정 속도에도 환산하며 발사자의 이동속도는 직접 섞지 않는다.

계산 필드는 `[tooltip=산식]현재값[/tooltip]`을 반환할 수 있다. 스킬 정보 본문은 현재 적용될 결과 숫자만 보여주고 hover에서 능력치 계수·기본값·레벨당 증가량을 설명한다. 실제 발동과 표시 계산은 같은 함수와 상수를 사용해 밸런스 변경 시 서로 어긋나지 않게 한다.

직업 공격 스킬의 복합 계수는 원본 스탯이 아니라 장비·패시브·상태효과를 모두 합산한 현재 `Attribute` 값을 읽는다. 따라서 이동속도·공격력·마법력·최대 생명력·제련 정밀도를 올리는 버프도 해당 계수를 즉시 증폭한다. 이동속도는 공격력보다 표시 단위가 작으므로 피해 산식 안에서만 전투력 단위 환산값을 적용하지만, 환산 전에 읽는 값은 현재 이동속도다. 직업별 기본 방향은 다음과 같다.

- 전사: 공격력을 가장 크게, 최대 생명력과 이동속도를 보조 계수로 사용한다.
- 궁수: 공격력을 주 계수, 이동속도를 보조 계수로 사용한다.
- 암살자: 이동속도를 주 계수, 공격력을 보조 계수로 사용한다.
- 마법사: 마법력을 주 계수로 사용하고 방어 스킬은 최대 생명력도 반영한다.
- 대장장이: 제련 정밀도가 공격력·최대 생명력 또는 엘리트 방향의 주 계수 효율을 추가 증폭한다.
- 엘리트: 메인 직업의 주 계수를 가장 크게 유지하고 서브 직업 능력치는 보조·3차 계수로 더한다.

### Lv.180 이후 메인 계보 성장

Lv.180 이후에는 보유 액티브 수를 계속 늘리는 대신 메인 계보의 역할을 강화한다. Lv.240에는 최대 레벨 1의 상시 패시브, Lv.320에는 최대 레벨 5의 역할기를 자동 획득한다. 두 단계 모두 `JobSlotType.MAIN` 요구 조건을 사용하므로 엘리트 전직 뒤에도 원래 메인 계보는 계승하지만, 서브 직업만으로는 같은 패시브·역할기를 추가 획득하지 않는다.

| 메인 계보 | Lv.240 패시브 | Lv.320 역할기 | 전투 역할 |
| --- | --- | --- | --- |
| 전사 | 불퇴의 체질 | 선봉의 호령 | 몬스터 교전·도발과 10초 일반 보호막 |
| 궁수 | 궤적 해석 | 파갑 표식 | 10초 물리 방어 약화 |
| 암살자 | 살수의 호흡 | 종막 | 잃은 생명력 기반 마무리 공격 |
| 마법사 | 심층 마력순환 | 마력 균열 | 10초 마법 방어 약화 |
| 대장장이 | 명장의 열처리 | 구조 해체 | 10초 물리·마법 방어 동시 약화 |

Lv.320 역할기의 재사용 대기시간은 레벨에 따라 20~30초 범위이며 기존 직업 계열 공유 쿨다운과 0.9초 전투 기술 연계 간격을 그대로 사용한다. 방어 약화기는 행동을 막는 군중 제어를 만들지 않는다. `종막`은 치명타를 발생시키지 않고 공격력·이동속도 환산값을 기준으로 잃은 생명력 보너스와 최종 피해에 각각 상한을 적용하며, 설명·실제 타격·밸런스 진단이 `calculateFinaleExecutionDamage()`를 공유한다.

Lv.500 3차 계승은 신규 액티브를 추가하지 않고 직업 지급 패시브와 기존 역할기 강화를 사용한다. 3차 패시브는 `skill:{id}:passive` 소스 하나만 능력치 modifier를 소유하고, 직업 요구 조건을 잃거나 관리자가 직업을 재설정하면 `SkillBook.revoke/onPassiveInactive`로 즉시 정리한다. 철혈군주 보호막·도발 1.22배, 월영집행자 상한 1.18배, 나머지 세 계보의 약화 +1레벨은 표시·실행·밸런스가 같은 helper를 쓴다.

`createBalanceScenario()`는 Lv.500 이상 진단에서 장기 퀘스트를 완수한 3차 표준 프로필을 명시적으로 가정한다. 이때 3차가 엘리트를 대체하지 않으며 원래 `eliteJob` modifier·패시브·액티브, 메인 계보 Lv.240/320 스킬과 3차 패시브를 함께 적용한다.

효과 설명은 `기술의 행동과 콘셉트 → 현재 계산된 결과 → 상태효과·보호막 같은 후속 효과` 순서의 자연스러운 한국어 문장으로 작성한다. 피해·회복·보호막 본문에는 플레이어가 즉시 비교할 최종값을 표시하고, `공격력 × 205%`, `최대 생명력 × 12% + 공격력 × 45%` 같은 산식은 그 최종값의 tooltip에 둔다. 능력치 아이콘 옆에는 `물리 관통력`, `마법 관통력`처럼 이름을 함께 표시하며 아이콘과 숫자만 기계적으로 나열하지 않는다.

액티브 스킬의 `activationConditionTemplate`에는 대상 지정, 필수 장비, 은신 같은 실제 준비 조건만 적는다. 제한이 없는 무기·대상이나 이미 획득한 직업·스킬북 경로는 반복하지 않으며, 아무 준비도 필요 없는 자기 강화기는 `/스킬 이름`과 `이름!` 입력 방법만 안내한다.

`SkillData.sharedCooldowns`는 `{ targetTag, seconds }` 목록이다. 발동 성공 시 `SkillBook.applySharedCooldowns()`가 해당 표시 계열 태그를 가진 보유 스킬의 남은 쿨다운을 최소 시간까지 올리며, 이미 더 긴 개인 쿨다운은 줄이지 않는다. 현재 전사·궁수·암살자·대장장이 계열은 0.75초, 모든 마법은 0.5초를 공유하고 화염·빙결·전격 계열은 같은 원소끼리 1초를 공유한다. 엘리트 액티브도 메인 계보와 속성 계열을 동일하게 적용한다.

플레이어의 `skill:combat` 사용형 기술은 개인·태그 공유 쿨다운과 별도로 성공 발동 사이에 0.9초의 전역 연계 간격을 공유한다. 조건 검사나 `onStart`가 실패하면 간격을 소비하지 않고, `reduceCooldowns()`도 이 비영속 간격을 줄이지 않는다. 평타·아이템·마력 제련 같은 생활 기술과 `SkillBook.createRuntime()` 몬스터 기술에는 적용하지 않는다. 관리자 밸런스 프로파일의 전투 로테이션도 동일한 전역 간격과 `sharedCooldowns`를 적용해 실제 전투보다 스킬 난사 화력을 과대평가하지 않는다.

`/스킬정보`는 raw tag key를 노출하지 않는다. `defineSkillTagDisplay()`에 등록된 직업·기술 계열과 `TagEffect`에 표시 metadata가 등록된 속성만 `계열`과 `속성`으로 나눠 보여주며, 공유 쿨다운도 `마법 보유 스킬 최소 0.5초`처럼 표시명·아이콘·시간만 출력한다.

### 밸런스 진단

권한 10 관리자용 `/스킬밸런스 <스킬> [스킬레벨] [캐릭터레벨] [직업]`, `/직업밸런스 [레벨] [메인직업] [서브직업]`, `/아이템밸런스 <아이템> [캐릭터레벨] [직업]`, `/밸런스프로파일(bp) [레벨|전체] [메인직업|전체] [서브직업]`은 `models/Balance.ts`의 같은 공개 분석 API를 사용한다. 관리자 페이지의 `전투 로테이션 프로파일`도 동일 API를 호출한다. CLI에서는 `cd server && npm run balance:report -- 50` 또는 `-- all`로 단일/전체 레벨 구간을 출력한다. `전체`는 공용 `BALANCE_PROFILE_LEVELS`의 Lv.20/50/75/100/140/180/200/350/500/750/1000을 사용하고, Lv.200 이상에서는 대장장이를 포함한 20개 엘리트 조합도 비교한다. 아이템 분석은 장비 modifier 또는 버프 아이템 metadata가 가리키는 실제 StatusEffect를 적용해 기본 공격 DPS·물리/마법 생존·능력치의 전후 차이를 표시한다.

개별 스킬/직업 기준선 외에 전투 프로파일은 실제 레벨 스탯, 직업별 공개 배분, 레벨대 추천 무기, 직업 패시브, 성장 시점에 맞춘 스킬 레벨을 적용한다. 추천 무기는 시작 장비 하나를 전 구간에 고정하지 않고 각 지역에서 실제로 회수 가능한 장비 단계로 교체하며, `createBalanceScenario`의 선택적 장비 ID로 같은 직업·레벨·대상에 다른 주무기를 강제해 비교할 수도 있다. 공개 배분은 전사 `근력>체력>민첩`, 궁수 `근력>민첩>감각`, 암살자 `민첩>근력>감각`, 마법사 `정신력>감각>체력`, 대장장이 `감각>체력>근력` 순서를 유지한다. Lv.200 대장장이 메인 엘리트는 서브 방향의 실제 무기와 별도 배분을 사용한다. 가장 가까운 실제 일반/보스 마스터의 저장된 프로필·체급·가중치로 원본과 목표 레벨 능력치를 각각 계산하고, 실제 원본/계산 원본 비율을 목표 계산값에 곱해 authored 성향을 보존한다. 몬스터 투영에는 플레이어 직업이나 스탯 배분을 사용하지 않는다. 일반전은 30초, 보스전은 240초 동안 하나의 행동 시간·정신력·개별/공유 쿨다운과 0.9초 전투 기술 연계 간격을 공유한다. 연계 대기 중에도 평타는 막지 않으며 평타를 최소 세 행동마다 한 번 섞고, 추천 주무기의 `weaponRequirement`를 만족하는 공격·방어·보조 스킬만 순환한다. 지속 능력치 버프는 실제 modifier와 지속시간으로 후속 공격에 반영한다.

공격 축은 분석창 평균 DPS와 `대상 HP ÷ DPS`뿐 아니라 누적 기대 피해가 대상 HP를 처음 넘은 실제 행동 시각, 치명타를 포함해 적중했을 때 가능한 최대 단발 피해, 첫 반격 전에 실행 가능한 기대 고피해 행동 묶음과 처치 여부를 함께 표시한다. CLI 보고서는 일반·보스 각 행에 실제 `report.duration`을 표시해 분석 시간을 고정 문구로 오해하지 않게 한다. 따라서 평균 DPS가 비슷해도 암살자·누커가 보스를 한 방에 처치할 가능성이 있거나 반격 전에 끝내는 경우를 별도로 식별한다. 근접 공격은 공격자 이동속도, 화살·마력 구체는 실제 투사체 가속으로 계산한 판정속도와 대상 회피율, 90% 회피 요구 속도·민첩, 장비 기본 관통과 스킬 고유 관통을 합친 유효 관통도 분리한다. 투사체 기본 공격은 마스터 데이터의 피해 배율·고정 피해와 투사체 자체 속성 상성을 반영하고, 회피 불가 스킬은 대상 속도와 무관하게 회피율 0으로 분석한다.

생존 축은 플레이어와 대상 최대 생명력, 대상의 실제 평타 피해·공격 주기, `MonsterData.skills/skillPattern`의 가장 강한 기술·회피 불가·즉사 여부를 읽는다. 같은 공격에 대해 무회피 생존시간, 플레이어 이동속도 회피를 적용한 생존시간, `balance.guaranteedEvasion` 지속 구간과 로테이션 회복·보호막까지 적용한 생존시간을 단계별로 계산한다. 실제 로테이션 처치 시점까지 예상 피격 횟수·피해·남은 생명력과, 회피가 없으면 죽지만 회피 덕분에 생존하는지도 함께 표시한다. 확정 회피는 공격 점수로 환산하지 않고 실제 가동 구간에 들어온 회피 가능한 타격만 제거하며 회피 불가 기술은 그대로 맞는다.

제어·은신·광역의 추가 대상·대상 생명력 비례 지속 피해는 임의 가중치를 부여해 단일 전투력에 섞지 않는다. 공격·생존·선공 폭딜도 하나의 임의 종합 점수로 합치지 않고 각 실측 축을 함께 비교한다. 직접 피해 속성만 `effectTags`로 명시해 실제 상성을 적용하므로 독을 바른 물리 칼날처럼 후속 효과만 독인 공격은 물리 타격 전체가 무생물 면역으로 사라지지 않는다. balance callback이 없는 스킬은 추정하지 않고 `미지원`으로 표시한다. 계수나 직업 modifier를 바꿀 때는 `-- all` 기준선을 전후 비교한다.

직업 귀속처럼 현재 사용할 수 없는 스킬은 DB에서 제거하지 않는다. `isVisible`과 `canUse`로 표시/사용만 비활성화한다. `SkillBook.grant()`는 신규 획득일 때 채팅과 notification에 `스킬 [ 이름 ] 를 획득했습니다!`를 보내며 이미 보유한 스킬은 중복 생성하지 않는다.

### Metadata와 계산 필드

`SkillData.baseMetadata`는 코드 기본값이고 인스턴스는 top-level delta만 `player_skills.metadata`에 저장한다. `getMetadata/setMetadata/resetMetadata`를 사용하며 raw JSON을 직접 수정하지 않는다. delta가 없는 필드는 코드 기본 metadata를 바꾸면 기존 스킬에도 즉시 새 값이 적용된다.

템플릿은 다음 값을 치환한다.

- `{{calc.damage}}` 또는 `{{damage}}`: `calculatedFields.damage({ player, skill })` 결과.
- `{{meta.baseManaCost}}`: metadata 유효값.
- `{{skill.level}}`, `{{skill.maxLevel}}`, `{{skill.name}}`.
- `{{skill.experience}}`, `{{skill.requiredExperience}}`: 현재 경험치와 다음 레벨 요구량.
- `{{maxCooldown}}`, `{{remainingCooldown}}`: 내장 계산값.

설명·소모·발동 조건은 모두 같은 포맷터를 사용한다. 결과 문자열은 `parseChatMessage()`를 거치므로 `[color=orange]{{damage}}[/color]`처럼 기존 채팅 전용 문법을 사용할 수 있다. 공격력/물리 피해는 주황색, 정신력은 상태창과 같은 `$magic` 보라색, 치명타·쿨다운 강조는 금색을 기본 표현으로 사용한다.

## 발동 경로와 수명주기

- `/스킬목록` 또는 `sl`: 현재 표시 가능한 보유 스킬의 아이콘·레벨·사용 상태와 정보 버튼을 표시한다. 패시브는 `패시브` 상태로 구분하며 사용 버튼을 만들지 않는다.
- `/스킬 스킬이름` 또는 `su 스킬이름`: 명령 입력은 숨기고 `SkillBook.activateByInput()`을 호출한다.
- `/스킬정보 스킬이름` 또는 `si 스킬이름`: 계산된 상세 정보, 현재 레벨과 경험치 진행도를 표시한다.
- 일반 채팅: 명령이 아닌 메시지를 각 스킬의 `activateOnMessage`로 검사하고 일치하면 원문 전송 대신 같은 발동 API를 호출한다.
- 자동 조건: 0.25초마다 현재 표시 가능한 스킬의 `autoActivate`를 검사한다.
- 자동 획득: 첫 update와 관련 progress 변경 후 `autoAcquire.watchedProgress`만 다시 검사한다. Progress key가 없는 현재 상태 조건은 `alwaysEvaluate`를 명시한 정의만 0.5초 주기로 검사한다. 스탯 100 달성형 히든 패시브와 현재 직업 계보·`unlockLevel`을 확인하는 Lv.30~180 성장 기술이 이 경로를 사용한다. 마법사 속성 상위 주문은 원소별 처치 counter를 구독하면서 선행 주문 레벨도 주기 검사해 두 조건을 모두 만족한 순간 획득한다.

## 고레벨 기술 진화·융합 검토

Lv.500 이후에는 새 액티브를 계속 추가하는 방식보다 기존 로테이션을 강화하는 진화·융합을 우선한다. 현재 `SkillBook`은 `grant/revoke`, 경험치·레벨·metadata delta 영속 API를 갖지만 둘 이상의 스킬을 원자적으로 교체하거나 성장치를 승계하는 목적형 API는 아직 없다. 따라서 실제 콘텐츠를 정의하기 전에 다음 공용 경계를 먼저 추가한다.

- `SkillEvolutionData`: 결과 스킬 ID, 선행 스킬과 요구 레벨·통계·직업/속성 조건, 경험치 승계율, 하위 기술 처리 정책을 마스터 데이터로 선언한다.
- `SkillBook.evolve(...)`: 모든 조건을 한 번 검증한 뒤 결과 기술을 지급하고 선행 기술을 `숨김 승계` 또는 `회수`한다. DB 저장은 결과 upsert와 회수 delete를 같은 Prisma transaction으로 처리한다.
- 단일 진화는 화염구→업화구처럼 기존 역할과 시전어를 유지한다. 융합은 화염구+폭풍 계열→뇌화성처럼 두 기술의 핵심 태그·계수를 합치되 공유 쿨다운도 두 계열에 모두 적용한다.
- 선행 기술 경험치는 결과 기술의 시작 경험치로 일부 승계하고, 이미 지급된 하위 기술을 다시 획득하거나 퀵 HUD에 중복 노출하지 않는다. 관리자 회수·재지급과 구형 DB 로드도 같은 공개 API를 사용한다.
- 진화 정보창은 선행 기술, 실제 최종 수치, 승계되는 속성·상태효과만 공개하고 내부 Progress key나 숨은 획득 정답은 노출하지 않는다.
- 권장 성장선은 Lv.500~700 단일 상위 진화, Lv.700~900 같은 직업/속성 내 2기술 융합, Lv.900~1000 엘리트 계보와 속성 트리를 합친 궁극 진화다. 한 로테이션의 표시 액티브 수는 크게 늘리지 않는다.

발동은 사망·활성 중·개인/공유 쿨다운·플레이어 전투 기술 연계 대기·`canUse/canActivate`를 검사한다. 쿨다운과 연계 대기가 함께 남았으면 더 긴 제한을 안내한다. 조건을 통과하면 선택적 `activationMessage`를 솔로에서는 시전자 본인에게만, 파티 중에는 시전자와 파티원에게 `[파티]` 필터 메시지로 전송한 뒤 `onStart`를 실행하므로 공격·회복 같은 즉시 효과보다 발동 메시지가 먼저 표시된다. 원래 입력한 일반 채팅 발동어는 공개 채팅으로 전달하지 않는다. `onStart`와 활성 상태 시작이 성공하면 쿨다운과 플레이어 전투 기술의 0.9초 비영속 연계 종료 시각을 확정하며, `activationFeedback`이 있으면 계산된 효과를 같은 audience의 봇 메시지와 notification으로 보낸다. 이 성공 확정 시점에 영속 플레이어 스킬은 기본 10 경험치를 얻고, 몬스터 런타임 스킬은 경험치를 얻지 않는다. 기본 다음 레벨 요구량은 `100 + (현재 레벨 - 1) × 50`이며 두 값 모두 SkillData 계산 함수로 재정의하거나 획득량을 0으로 끌 수 있다. 요구량을 넘긴 잔여 경험치는 다음 레벨에 이월되고 최대 레벨에서는 더 이상 누적하지 않으며, 레벨업 시 본인 메시지와 notification을 보낸다. 지속시간이 있으면 `onUpdate`, 종료 시 `onFinish`를 호출한다. 로그인 중 표시·사용 조건을 만족하는 패시브에는 `onPassiveUpdate`, 조건을 잃거나 회수될 때는 `onPassiveInactive`를 호출해 runtime modifier를 source 단위로 정리한다. 로그아웃 시 활성 스킬을 `UNLOADED` 사유로 종료한 다음 저장한다.

은신은 대상 지정 방지와 이동속도 증가를 제공하지만 공격 준비가 실제로 통과한 직접 공격 또는 투사체 생성 순간 즉시 해제된다. 빗나가거나 상대가 회피해도 공격 행동 자체가 확정됐으므로 다시 숨지 않는다. 궁수의 `바람 회피`는 Lv.1 2.5초에서 레벨당 0.25초씩 증가하고 기본치를 넘는 이동속도 1당 0.005초를 더하되 최대 4초로 제한한다. 재사용 대기시간은 24초에서 레벨당 1초씩 줄어 최소 20초이므로 최대 가동률은 20%다. 이동·회피 행동이 허용되는 동안 같은 server tick의 연속 공격과 다단히트를 포함해 들어오는 모든 일반 공격을 확정 회피한다. `unavoidable` 회피 불가 공격은 지속형 확정 회피보다 우선하며, 공명 파편의 다음 공격 1회 회피와는 별도 source로 관리한다.

모든 SkillData는 `skills/{skillId}.png` 128×128 전용 아이콘을 사용한다. 시전 메시지가 있는 스킬은 `skill-headers/{skillId}.png` 256×64 전용 배너를 같은 플레이어 메시지 상단에 붙인다. 배너와 시전어는 솔로 본인 또는 현재 파티라는 기존 audience 규칙을 함께 따른다.

## 스킬 퀵 HUD

`skill:passive` 태그가 있는 패시브는 스킬 목록과 정보창에는 노출하지만 직접 누를 수 있는 퀵 HUD payload와 사용 자동완성에서는 제외한다.

`SkillBook.getHudSnapshots()`은 `isVisible`을 만족하는 보유 스킬의 ID, 표시명, 아이콘, 레벨, 발동 상태, 남은/최대 쿨다운을 0.5초 `playerStats.skills`에 싣는다. 플레이어 전투 기술에만 선택적 `cadenceRemaining/cadenceDuration`을 더하고 생활 기술과 런타임 몬스터 snapshot에는 넣지 않는다. 클라이언트 HUD 설정의 `전투 퀵 버튼`에서 기본 공격과 각 스킬 버튼을 개별 On/Off할 수 있으며 선택과 viewport `%` 좌표는 계정 ID로 분리된 localStorage에 저장된다. HUD 전체 설정은 이름 있는 서버 프리셋에도 포함되며 사용자가 저장된 이름을 선택해 불러올 때만 적용된다. 설정 목록은 기본 접힘 상태이고 활성/전체 개수를 요약하며, 펼친 목록은 제한된 높이 안에서 별도로 스크롤한다. 제목 옆 톱니 설정은 전투 퀵 버튼에만 적용되는 50~200% 크기를 별도로 저장한다. 새 전투 버튼은 PC 8열·모바일 4열 기본 격자에 놓이고 위치 편집 모드에서 각각 독립적으로 이동하거나 초기화할 수 있다. 공격 버튼은 `playerStats.attackCooldown/maxAttackCooldown`을 같은 시계 방향 overlay로 표시하고 기존 `/공격` 명령을 숨김 실행해 현재 지정 대상과 서버 공격 규칙을 그대로 재사용한다.

활성화된 버튼은 큰 스킬 아이콘과 아래의 작은 표시명을 가진다. 클릭은 공개 채팅을 만들지 않는 `chatButtonClick`의 `/스킬 이름` 동작을 사용하므로 모든 실제 조건 검사는 기존 `SkillBook.activateByInput()` 경로를 그대로 따른다. 개인/공유 쿨다운과 전투 기술 연계 대기 중 더 긴 시간을 payload 수신 시각부터 0.1초 단위로 보간하고, 완전히 어두운 상태에서 투명 영역이 시계 방향으로 늘어나는 overlay와 남은 초를 표시한다. tooltip은 원인에 따라 `재사용 대기`와 `전투 기술 연계 대기`를 구분한다.

## 강타

첫 스킬 `power_strike`(강타)는 치명타 누적 5회에 자동 획득한다.

- `/대상지정 번호`로 선택한 같은 위치의 살아 있는 오브젝트를 공격한다.
- `/스킬 강타` 또는 일반 채팅 `강타!`로 발동하고, 조건 통과 시 플레이어가 보낸 `강타!` 메시지를 공격 결과보다 먼저 채널에 남긴다.
- 정신력을 소모하고 현재 공격력·레벨 배율로 물리 공격을 수행한다.
- 검·도끼·단검·곡괭이 중 하나를 주무기로 장착해야 하며 활·지팡이를 근접 무기처럼 사용해 투사체 규칙을 우회할 수 없다.
- 해당 공격의 치명타율만 100%로 override한다.
- 공격 전 `armorPen +10`과 `armorPen ×1.05` modifier를 추가하고 공격 확정 직후 `source` 단위로 제거한다.
- 일반 `Entity.attack()`을 사용하므로 방어·상성·자원 도구 제한·공격 쿨다운·주무기 내구도 규칙을 그대로 따른다.

`/스킬정보 강타`는 레벨, 계산된 설명, 소모값, 재사용 대기시간, 포맷된 발동 조건을 각각 구분해 표시한다.

## 지각 붕괴와 몬스터 스킬

`seismic_crush`(지각 붕괴)는 1.8초 시전 예고 후 현재 대상에게 마법 피해를 주고 확률적으로 마비독을 부여한다. 플레이어는 정신력을 소모하지만 Monster 런타임 시전에는 플레이어 자원 비용이 없다. `SkillBook.activateById()`가 몬스터 패턴의 공개 발동 경계이며, `MonsterData.skills`가 보유 ID·레벨을, `skillPattern`이 순환 순서·첫 지연·반복 간격을 정의한다. 시전 중에는 일반 공격을 수행하지 않는다.

성장 구간 보스는 이 경계를 그대로 사용해 초반의 `적갈기 도약`, `은실 포박`, `유충의 맹독`부터 황혼왕릉의 `백골 왕명`·회피 불가 `파계 처형`, `칼데라 분출`, `천둥 과부하`, 유리모래 사막의 `모래 맹독 탄막`·`석화 태양시선`·`태양고 섬광`, 설원의 `상고발톱 그물비`·회피 불가 `빙경 관통창`·`극광 침묵`, 해안의 `해무 합창`·`역조 침묵`, 침몰왕도의 `제독의 심해 닻`·`침수 함대 명령`, 카이로스 공방도시의 `태엽 과주행`·회피 불가 `시간강 정지추`·`인과 절단`·`광자 판결`, `밤숲 가시`, `밤숲 재생`, `성역 심판`, `불사 진혼곡`까지 발동한다. Lv.400 이후에는 중력 망치·낙성·사건지평, 영시 절단·진자뢰·시간정지·역행, 성단 신성·침묵·붕괴·창세·소멸의 13개 보스 기술이 추가된다. 각 스킬은 피해 타입·상태이상·회피 가능 여부를 자체 정의하며 `skillPattern.randomOrder` 보스는 현재 발동 가능한 후보를 무작위 시작점부터 탐색한다. 별도 미니게임이 없는 보스도 실제 공용 스킬·랜덤 패턴·주변 오브젝트 기믹·높은 보상으로 일반 몬스터와 구분한다.

은빛그물 숲의 적갈기 늑대왕과 거미여왕은 각각 `포식자의 도약`, `은실 사냥망` 플레이어용 전승서를 3.5%·3%로 드롭한다. 몬스터 전용 패턴 SkillData를 그대로 지급하지 않고 플레이어 자원·쿨다운·설명·밸런스 metadata가 있는 별도 기술로 변환하며, 직업 제한 없이 스킬북을 사용한 캐릭터가 배운다.

피버릭 갱도 수정 왕좌의 보스 `수정맥의 군주`는 지각 붕괴 3레벨을 5초 뒤 처음 사용하고 이후 10~13초마다 반복한다. 낮은 확률로 `지각 붕괴 스킬북`을 드롭하며, 사용 시 `SkillBook.grant()`를 통해 영속 플레이어 스킬로 교환된다. 이미 보유한 경우 아이템을 소비하지 않는다.

스킬 정의에는 `/icons/{SkillData.icon}.png` 에셋이 필수다. 스킬 목록과 정보창은 아이콘을 이름 앞에 표시하며, 스킬 아이콘은 아이템과 달리 속성색을 담은 불투명 카드형 배경을 사용할 수 있다.

현재 스탯 100 달성 시 각각 `거인의 힘`, `바람걸음`, `불굴의 육체`, `심안`, `마력의 샘`을 자동 획득한다. 모두 항상 적용되는 숨김 패시브이며 각 스킬 ID의 전용 아이콘을 사용한다.

대장장이 계보는 감각 250 이상을 `alwaysEvaluate`로 검사해 유틸리티 패시브 `장인의 명명`을 자동 획득한다. 직접 발동하는 스킬 버튼 대신 `/장비명명` 명령에서 제작자 소유권과 이름 형식을 검사한다.

1차 직업은 전직 지급 기술 외에도 다음 성장 기술을 자동 획득한다. 엘리트 직업도 `CareerProfile.hasJob()`의 하위 계보 호환으로 원래 메인 직업 기술을 계속 획득·사용한다.

- 전사: Lv.30 `파쇄 베기`, Lv.50 `철풍 돌파`, Lv.75 `전선 가르기`·`방패분쇄`, Lv.100 `철혈 반격`·`혈기 폭풍`, Lv.140 `거인 단두`·`대지 가르기`, Lv.180 `전쟁신 강림`·`최후 군단`.
- 궁수: Lv.30 `관통 화살`, Lv.50 `화살 폭우`, Lv.75 `추적 화살`·`풍절 화살`, Lv.100 `파열 연사`·`구속 화살`, Lv.140 `유성 화살`·`태양 관통`, Lv.180 `천궁 낙화`·`성우`.
- 암살자: Lv.30 `혈맥 절단`, Lv.50 `그림자 단검`, Lv.75 `독영 투척`·`신경침`, Lv.100 `그림자 추격`·`안개걸음`, Lv.140 `심장 적출`·`사점 낙인`, Lv.180 `무영 연살`·`무월 처형`.
- 마법사: Lv.30 `마력 창`, Lv.50 `홍염 파동`, Lv.75 `마력 폭쇄`, Lv.100 `마도 유성`, Lv.140 `원소 붕괴`, Lv.180 `성좌 파열`.
- 대장장이: Lv.30 `결함 간파`, Lv.50 `모루의 공명`·`담금질 방벽`, Lv.75 `열점 타격`, Lv.100 `강철 맥동`, Lv.140 `극정밀 파쇄`, Lv.180 `모루성 낙하`. 상위 공격은 공격력·최대 생명력에 더해 감각 파생 `제련 정밀도`가 주 능력치 계수를 추가 증폭하며, 최종 숫자의 tooltip과 실제 공격·밸런스 callback이 같은 산식을 사용한다.

마법사는 기본 화염구·빙결탄·뇌전구에서 세 속성을 독립적으로 성장시킨다. 각 계열은 속성 몬스터 처치 30/100/200회와 직전 단계 주문 Lv.3/Lv.3/Lv.4, 캐릭터 Lv.75/140/180을 함께 요구한다.

- 화염: `작열창` → `불사조 폭염` → `겁화 유성`.
- 빙결: `서리 감옥` → `빙하 첨탑` → `절대영도`.
- 전격: `뇌광창` → `연쇄 뇌격` → `천뢰 심판`.

궁수의 기본·성장 화살은 공격력과 현재 이동속도를 함께 사용하고, 암살자의 기본·성장 공격은 현재 이동속도를 주 계수로 공격력을 보조 계수로 사용한다. 바람 회피·충격 화살의 기절·은신 지속시간도 기본치를 넘는 현재 이동속도에 따라 늘어나며, 바람 회피는 공용 계산 함수에서 4초 상한을 적용해 표시·실제 효과·밸런스 진단이 같은 값을 사용한다.

성장 기술의 실제 피해·관통·회피 불가·투사체 치명타·상태효과·보호막 callback은 설명과 `Balance`가 공유한다. `마력 보호막`은 마법력·최대 정신력·최대 생명력에 Lv.50 이후 최대 3배의 성장 보정을 적용하는 전용 마법 방벽이다. 마법 계열 공격 뒤 생기는 일반 방벽도 같은 네 성장축을 사용하되 전용 방어기보다 낮은 계수를 사용한다. 복합 계수 투사체는 계산된 최종 기본 피해를 생성 시점에 넘겨 표시·진단과 실제 적중이 같은 값을 사용한다. 회피 불가 투사체는 `ProjectileDataOverrides.unavoidable`이 비행 뒤 실제 `Entity.attack()`까지 보존된다. Lv.75/100/140/180 추천 장비·동레벨 보스 60초 회귀 프로파일은 다섯 1차 직업의 최고/최저 DPS 비율을 1.55배 이내로 검사한다. 한 주무기만 사용하는 Lv.200의 순서 있는 20개 엘리트 조합은 무기 조건과 상성까지 반영한 1.7배 이내를 검사한다. 전직 직후 Lv.1인 조합 전용기는 직접 피해에 물리 3배·마법 4.6배 티어 보정(마검사 별도값)을 적용하고, 치명타·상태효과·보호막을 합산하지 않아도 성장한 일반 공격기의 직접 피해 68% 이상을 유지한다. 강화 후 프로파일도 평타 피해 비중을 최소 13% 남긴다. 초급 마법사는 잡화점의 성휘목 지팡이, Lv.40 전후에는 애도목 지팡이를 기준으로 하며 마법 기본 공격용 마력 구체는 현재 마법력의 108%를 피해 기준으로 사용한다.

카이로스 공방도시에서는 직업 제한 없는 성장 기술 네 종을 전승서로 획득한다. `광자창`은 광속성 마법 투사체와 마법 관통을, `인과고정`은 회피 불가 암속성 피해·마법 관통·속박을, `톱니폭우`는 세 발의 금속 물리 투사체와 물리 관통을, `역설반전`은 회피 불가 광속성 피해와 마법력·최대 정신력·최대 생명력 비례 일반 보호막을 제공한다. 실제 발동과 정보창·관리자 밸런스 보고서는 같은 피해·관통·회피 가능 여부 callback을 사용한다.

벨카인에서는 직업 제한 없는 전승 기술 `공허걸음`과 `왕관무효`를 획득한다. 공허걸음은 회피 불가 물리 피해·물리 관통·실명을, 왕관무효는 회피 불가 마법 피해·마법 관통·침묵과 마법력·최대 정신력·최대 생명력 비례 보호막을 제공한다. 둘 모두 스킬 ID별 전용 아이콘과 시전 배너를 사용하며 실제 피해·관통·보호막 callback을 밸런스 보고서와 공유한다.

루나리스 해구에서는 직업 제한 없는 전승 기술 `역조보법`과 `월식선고`를 획득한다. 역조보법은 회피 불가 물리 피해·물리 관통·둔화를, 월식선고는 회피 불가 마법 피해·마법 관통·실명과 마법력·최대 정신력·최대 생명력 비례 보호막을 제공한다. 둘 모두 스킬 ID별 전용 아이콘과 시전 배너를 사용하며 실제 피해·관통·보호막 callback을 밸런스 보고서와 공유한다.

마도 대장장이 엘리트 전직은 `마법 부여`를 직접 지급한다. 명령형 후가공 스킬은 UI 버튼에서 인자를 받을 수 없으므로 패시브로 표시하고 `/마법부여`가 대상·자원·중복을 검증한다. 상태이상 외에도 추가 피해·회복·보호막·피해 변동·추가 투사체·현재 생명력 비례 피해가 후보에 포함되며 `/마법부여효과`와 성공 결과가 선택된 효과의 실제 수치를 설명한다. 성공할 때만 기본 스킬 경험치 25를 얻는다.

Lv.200 엘리트 직업 20개는 계승 패시브와 별도로 조합 전용 액티브 1종을 지급한다. 기존 네 전투 계열에 대장장이 메인/서브 조합의 금속 물리 공격·기공 투사체·독금·룬 마법·보호막 계열을 추가한다. 전용기는 Lv.1부터 엘리트 기술 티어를 가지며, 최종 피해 숫자 hover에서 기본 복합 계수와 티어 배율을 함께 확인할 수 있다. 피해·정신력·쿨다운은 모두 `SkillData.balance`와 실제 발동 계산을 공유하며 계승 패시브와 액티브 모두 스킬 ID별 전용 아이콘을 사용한다.

마검사의 조합 전용기 `마력 검파`는 전사 계보의 검뿐 아니라 도끼도 주무기로 인정한다. 발동 조건과 정보창 문구는 같은 `weaponTags` 정의를 사용한다. 공격력·마법력·이동속도 복합 계수는 유지하지만 이동속도 반영은 낮은 보조 시너지로 두고 마법력을 두 번째 성장축으로 강화한다. 별의 직조사의 `낙성`은 마법력 주계수와 이동속도 보조 계수에 낮은 공격력 계수를 더해 활 장착으로 얻는 공격력도 피해에 반영한다. Lv.200 보스 프로파일은 궁수+마법사의 `뇌광 관통화살`과 마법사+궁수의 `낙성`을 함께 비교해 단발·분당 피해가 세 계수라는 이유만으로 앞서지 않는지 검사한다.

`마력 보호막`의 현재 타입은 `GENERAL`이며 기존 성장 계수로 계산한 보호막이 물리·마법·고정 피해를 모두 흡수한다. 같은 지속시간의 방어력·마법 저항력 버프는 유지한다.

## 영속성

로그인 시 `Player.loadByUserId()`가 `PlayerProgress`와 `SkillBook`을 Inventory/Equipment와 함께 로드한다. 경험치 획득과 레벨업을 포함한 모든 변경은 메모리에 적용하고 versioned dirty key를 남긴다. `Player.save()`가 30초 주기, unload, 종료 시 `player_progress`와 `player_skills`를 upsert/delete한다. 저장 도중 같은 값이 다시 바뀌면 이전 snapshot 완료가 새 dirty version을 지우지 않는다.
