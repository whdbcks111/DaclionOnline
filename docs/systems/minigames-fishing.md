# 미니게임·낚시 시스템

## 공용 미니게임 세션

미니게임은 서버가 `startMiniGame()`으로 userId에 일회성 session ID·검증 token·만료 시각·타입별 config를 발급하고 `miniGameStart`로 해당 사용자의 모든 소켓에 보낸다. 한 사용자는 동시에 하나의 미니게임만 실행한다.

클라이언트는 결과나 입력 이력을 사후 제출해 확정하지 않는다. `MiniGameOverlay`는 렌더링 준비 시 `miniGameReady`, 이동 축이 바뀔 때 `miniGameInput`, 단조 타격 순간 `miniGameAction`을 보내며 서버가 각 이벤트의 실제 수신 시각으로 입력 trace를 누적한다. 종료 시 `miniGameResult`에는 session ID와 token만 보내 결과 확정을 요청한다.

- 현재 Socket.io 세션의 userId와 미니게임 소유자
- 일회성 session ID와 24-byte token
- 준비 이벤트부터 잰 서버 경과 시간, 타입별 제한 시간, 서버가 수집한 입력 개수·범위·시간 순서
- 타입별 validator가 원본 config로 재현한 실제 성공 조건

검증이 끝난 세션은 성공/실패와 관계없이 즉시 소비한다. 타입 소유 기능이 전투 종료 등으로 명시적으로 취소한 경우만 `miniGameCancelled` 정리 callback을 사용한다. 입력을 소유한 socket의 연결 종료·새로고침, 제한 시간 만료, 비정상 조기 완료는 취소가 아니라 실패로 확정해 `onResolved({ success: false })`를 실행하므로 보스 패턴 피해를 건너뛸 수 없다. 새 퍼즐·보스 패턴은 `shared/minigames.ts` DTO와 결정론 로직, `modules/minigame.ts`의 세션 validator, 클라이언트 renderer를 같은 변경에 추가한다.

`hazard_dodge`는 정해진 시간 동안 플레이어 토큰을 움직여 seed 기반 폭탄·가로/세로 레이저를 피하는 공용 보스 패턴 미니게임이다. 기본 `bombs/lasers/mixed` 외에 `chain_bombs`, `resonance`, `crossfire` 모드를 지원하고, 보드 이동속도는 실행 시점 Player `speed`의 18배를 10~48 범위로 제한해 동기화한다. `chain_bombs`는 중앙 예고 원이 커진 뒤 상하좌우 폭발로 이어지고, `resonance`는 일반 폭탄·레이저 사이에 세 줄 레이저를 110ms 간격으로 연사하며, `crossfire`는 폭탄 없이 가로·세로 레이저를 140ms 간격으로 교차 발사한다. 난이도 1~6은 기존 일반 패턴 밀도이고 7~10은 위험 구역 크기와 생성 간격이 함께 강화되는 후반 보스 구간이다.

## 보스 패턴 연결

`MonsterData.challengePattern`은 handler key, 첫 발동 지연, 반복 범위를 가진다. Monster는 현재 위협 대상에게 등록 handler를 실행하고 미니게임이 해결될 때까지 일반 공격과 다음 스킬을 멈춘다. 대상 이탈·보스 사망·리스폰은 보유한 취소 callback을 실행하고 오래된 완료 callback은 generation으로 무시한다.

`data/bossPatterns.ts`는 `hazard_dodge`를 실제 전투에 연결한다. 입력 trace는 관리자 테스트와 같은 `simulateHazardDodge()`로 재현하고, 실패 시에만 같은 장소의 생존 대상에게 최대 생명력 비례 고정 마법 피해를 준다. 미니게임을 이미 수행 중인 플레이어에게는 새 세션을 덮어쓰지 않고 보스가 짧게 재시도한다.

- 수정맥의 군주: 난이도 3 청록색 중앙 성장·상하좌우 연쇄 낙석, 실패 시 최대 생명력 18%
- 철근 심장수호자: 10초 폭탄+레이저+세 줄 레이저 연사, 수정 파괴 후 난이도 8·실패 시 최대 생명력 45%, 수정 생존 시 난이도 10·실패 시 60%. 실패 대상은 4초간 제압된다. 별도 `철근 압살`은 현재 위협 대상 한 명에게 회피 불가·방어 무시 25% 최대 생명력 피해와 3초 확정 제압을 준다.
- 성계 문지기: 10초 난이도 8 보라색 가로·세로 시간차 교차 레이저 전용 패턴, 실패 시 최대 생명력 50%와 5초 실명

`forge_rhythm`은 서버가 전달한 박자 시각에 Space·Enter·모바일 타격 버튼을 누르는 단조용 리듬 미니게임이다. 난이도별 생성기는 정박 외에 0.75/1.25박 엇박과 0.5박 연타를 섞고, 클라이언트는 사용자 입력으로 오디오가 활성화된 뒤 접근 cue와 망치 충격음을 재생한다. 단조 진입 시 채팅 입력 포커스를 해제해 터치 버튼이 모바일 키보드를 다시 열지 않으며, 모바일 timeline은 선행 표시 시간을 줄이고 번호 note와 시간 guide를 사용해 연타를 분리한다. 화면용 터치 시각 보정은 판정 원본이 아니며 각 `strike`는 발생 즉시 서버로 전송되어 서버 수신 시각으로만 기록된다. 서버와 클라이언트는 같은 perfect/hit 허용 시간으로 적중·미스·최대 콤보·원 정확도를 계산한다. 각 타격은 가장 가까운 미사용 note에 먼저 배정해 놓친 앞 note가 다음 연타의 정확한 입력을 가로채지 않으며, 진행 정확도는 이미 적중 또는 미스로 확정된 note만 분모로 사용한다. 종료 시에는 모든 note가 확정되므로 같은 값이 최종 서버 판정과 품질에 사용된다. 성공 기준을 넘은 어려운 패턴은 난이도 품질 보정을 더하며 validator의 최종 0~1 `score`가 문자열 재해석 없이 대장장이 완성품의 능력치·내구도 품질에 직접 연결된다. 관리자 패널의 테스트 카테고리는 낚시·일반 위험 회피와 세 보스의 연쇄 낙석·공명 폭주·성계 교차포화에 더해 기초/고속 단조 프리셋을 보상 없이 선택한 온라인 플레이어에게 실행한다.

## 낚시 흐름

낚시 보상은 `Fishing`의 장소별 테이블 registry를 우선 사용한다. `defineFishingTable(locationId, entries)`의 각 장소는 독립적인 물고기 ID 풀과 내부 가중치를 가지며, 추첨 때 플레이어 행운의 등급 확률과 장소 가중치를 합성한다. 테이블이 없는 기존 낚시터는 전역 등급 풀을 그대로 사용한다.

Lv.500 이전에는 유리모래 숨은 별빛 오아시스·안개파도 청해초 물목·카이로스 공방도시 잔해호·루나리스 해구 희미한 산호초·라그나벨 저문별 호수가 성장 구간별 낚시터다. 다섯 장소는 각각 전용 어종 2종과 기존 어종 3종을 섞은 독립 테이블을 사용한다.

Lv.575~975 승천 권역에는 압해 석호·먹물꿈 연못·수은 저수지·무언 기도샘·창세 조수대가 있다. 다섯 장소는 각각 전용 어종 3종을 포함한 별도 테이블을 가진다. 물고기 아이템은 그대로 섭취할 수 있고, 장소별 희귀 어종은 생선 버프 요리 5종의 제작 재료가 된다.

포획에 성공하면 장소별 `defineFishingTreasureTable()`을 물고기와 별도로 추첨한다. 기본 보물 확률은 초보 연못 0.6%, Lv.500 이전 단계별 낚시터 1~2%, 승천 권역 2.2~3%이며 행운 1당 기본 확률을 0.5%씩 상대 증가시킨다. 행운 100에서 최대 1.5배로 고정되어 과도한 보상 인플레이션을 막는다. 보물 표에는 10~30% 경험 증폭 물약, 단계별 희귀 제련 소재, 지역 버프 소모품과 약 2% 내부 가중치의 희귀 전승서가 들어간다.

1. `location:fishing` 태그 장소에서 손 슬롯에 `tool:fishing` 낚싯대를 장착한다. `/낚시` 실행 시 보조 슬롯에 `item:bait` 미끼가 없으면 `Inventory.findFirstItem()`으로 인벤토리 미끼를 찾아 묶음 전체를 보조 슬롯에 자동 장착한다.
2. `/낚시`는 낚싯대·장소·생존 상태를 검사하고 장착된 미끼 스택에서 하나만 소비한다. 남은 묶음은 보조 슬롯에 유지되고 `Equipment.count`로 저장된다.
3. 현재 행운·입질 속도·낚싯대 채집 능력을 snapshot하고 45~65초 기본 범위를 `fishingBiteSpeed`로 나눈 시간만큼 기다린다. 별도의 강제 최솟값은 없으며, 기본 능력치 1 + 초보자 낚싯대 0.1 + 지렁이 미끼 0.35 조합은 약 31~45초를 기다린다. 대기 notification은 남은 시간을 추측할 수 있는 길이 progress를 표시하지 않는다. 장소를 벗어나거나 낚싯대를 바꾸면 입질이 취소된다.
4. 입질 시 행운을 반영한 가중치로 일반/고급/희귀/서사/전설/신화 등급을 결정하고 progress 없는 경고 notification을 먼저 보낸다. 1초의 준비 시간이 지난 뒤 상태를 다시 검증하고 등급별 난이도의 `fishing_capture` 미니게임을 시작한다. `/낚시등급표`는 현재 장비·미끼·버프가 반영된 행운으로 같은 가중치 API를 계산해 실제 등급별 확률을 표시한다.
5. 성공하면 해당 등급 pool에서 물고기 하나와 현재 캐릭터 레벨·등급에 따른 경험치를 지급하고, 낮은 확률로 장소별 낚시 보물을 추가한 뒤 `fishing:fish_caught` 이벤트를 발행한다. 일반 물고기는 동레벨 일반 몬스터 한 마리 경험치의 70~90%(평균 80%), 고급 85~105%, 희귀 105~130%, 서사 135~170%, 전설 190~240%, 신화 300~400%다. 인벤토리 중량이 부족하면 물고기와 보물은 현재 장소 바닥에 떨어지지만 낚시 성공 이벤트와 튜토리얼 진행은 유지된다.

기본 등급 가중치는 62/22/9/4.5/2/0.5다. 행운은 일반 비중을 줄이고 상위 단계일수록 더 큰 비율로 가중치를 높이며 0~100 범위로 제한해 계산한다.

등급별 상점 매입가는 일반 5, 고급 20, 희귀 90, 서사 400, 전설 1,800, 신화 8,000 Gold다. 포획 난이도와 희소성을 보상하도록 다음 단계마다 약 4~5배씩 가치가 상승하며, 가격 단일 원본은 `FishRarity.sellPrice`다.

## 포획 미니게임

게이지는 기본 50%에서 시작한다. 물고기가 채집 영역 안에 있으면 상승하고 밖에 있으면 하락하며 100%는 성공, 0%는 실패다. 클라이언트는 0~1 값을 좌측 기준 `scaleX`로 0~100% 전체 트랙에 표시하고, 현재 값이 낮으면 빨강에서 시작해 주황·초록을 거쳐 성공에 가까울수록 파랑이 되는 단색을 사용한다. 수면 보드·채집 영역·조이스틱도 테마 단색 면과 얇은 경계를 사용하며 장식성 gradient나 glow를 사용하지 않는다. 표시 숫자는 실제 100%가 되기 전 100으로 반올림하지 않는다. 물고기 경로는 seed·난이도·경과 시간으로 결정되어 서버와 클라이언트가 같은 위치를 계산한다.

- PC: WASD 또는 방향키
- 모바일/터치: 원형 아날로그 조이스틱
- 낚싯대 metadata: `fishingNetShape` (`circle | square | rectangle`)
- 능력치: `luck`, `fishingBiteSpeed`, `fishingNetSize`, `fishingNetSpeed`, `fishingGaugeStart`

클라이언트는 축 입력 변화를 즉시 보내고 서버는 재생 해상도와 같은 20ms 구간별 마지막 수신값만 최대 2,048개까지 보존한다. 결과 요청 시 서버가 이 권위 trace를 20ms 고정 간격으로 재생해 채집 영역 이동 제한, 물고기 포함 여부와 게이지를 다시 계산한다. 클라이언트가 보낸 성공 boolean·경과 시간·임의 점수·사후 입력 배열은 계약에 존재하지 않으며 신뢰하지 않는다.

## 초기 콘텐츠

- 장소: 광장과 연결된 `루미나르 물빛 연못`
- 장비: 초보자·정교한 낚싯대와 보물상자 전용 범위 특화 `너울그물 낚싯대`·속도 특화 `급류바늘 낚싯대`, `/낚시` 시 묶음 자동 장착 `통통한 지렁이 미끼`
- 물고기: 공용 36종, Lv.500 이전 전용 10종, 승천 권역 전용 15종으로 총 61종. `data/fishingCatalog.ts`가 아이템 정보와 낚시·보물 보상 pool의 단일 원본이다.
- 상점: 루미나르 물빛 연못의 낚시상점에서 초보자·정교한 낚싯대와 미끼 판매, 등급별 물고기 매입

각 물고기는 `item:fish`, `property:water`, `fish_rarity:*` 태그를 가지며 상점은 개별 ID가 아니라 등급 태그로 매입한다. 따라서 카탈로그에 같은 등급의 물고기를 추가하면 낚시 pool과 상점 매입에 함께 반영된다. 낚시 아이템과 신규 능력치는 모두 대응하는 128×128 투명 캐주얼 아이콘을 가진다.
