# 파티 시스템

파티는 서버 프로세스 메모리에서만 유지되는 최대 5명의 온라인 협동 단위다. DB에 저장하지 않으며 마지막 연결 종료·명시적 나가기·강퇴·해산 때 즉시 정리된다.

## 수명주기와 공개 API

`modules/party.ts`의 `partyManager`가 내부 Party/초대 Map을 단독 소유한다. 외부 코드는 raw 멤버 배열을 수정하지 않고 다음 API만 사용한다.

- `invite/accept/decline`: 60초 초대 생성과 수락·거절. 파티가 있으면 파티장만 초대할 수 있고 수락 시점에도 정원과 파티장 상태를 재검사한다.
- `leave/disband/kick`: 나가기, 파티장 전용 해산, 파티장 전용 강퇴. 파티장이 나가면 가입 순서상 다음 멤버가 파티장이 되고 1명만 남으면 파티를 종료한다.
- `removeDisconnectedPlayer`: 마지막 소켓이 끊기거나 Player가 unload될 때 파티와 초대를 정리한다.
- `getParty/getHudData`: 변경 불가능한 구성 snapshot과 현재 생명력·정신력 HUD DTO를 반환한다.
- `areInSameParty`: 두 userId가 같은 파티인지만 반환해 PVP에서 아군 공격을 차단한다.
- `getEventAudienceUserIds`: 스킬·전투 피드를 받을 파티원 ID snapshot을 반환한다. 파티가 없으면 본인만 반환한다.
- `distributeMonsterExp`: 몬스터가 reset 전에 복사한 교전 claim·기여도 문맥을 받아 유효 참여자를 검증하고, 정수 경험치 풀을 기여도에 따라 배분한 뒤 개인별 실제 지급 결과를 반환한다.
- `calculatePartyExpPool/allocateContributionWeightedExp/calculatePartyExpGrant`: 유효 인원수에 따른 전체 풀, 균등·기여 가중 Hamilton 배분, 개인 레벨 차이 감쇠를 각각 순수 계산한다.

닉네임 또는 고유번호 대상 조회는 `playerRegistry.findOnlinePlayerByIdentity()`를 사용한다. 닉네임은 대소문자를 무시한 정확한 일치이고 고유번호는 양의 정수 또는 `#번호` 형식을 허용한다.

## 명령어

- `/파티초대 고유번호 또는 닉네임`: 온라인 비파티 플레이어에게 초대. 초대 메시지에 수락·거절 버튼을 제공한다.
- `/파티수락`, `/파티거절`: 가장 최근의 유효한 초대를 처리한다.
- `/파티정보`: 파티장, 레벨, 같은 장소 여부와 HP/MP를 표시한다.
- `/파티나가기`: 본인이 이탈한다. 파티장이면 파티장 권한을 이전한다.
- `/파티강퇴 고유번호 또는 닉네임`: 파티장만 같은 파티의 다른 멤버를 강퇴한다.
- `/파티해산`: 파티장만 전체 파티를 종료한다.

초대·수락·강퇴 같은 조작 결과는 정보 공개 모드와 관계없이 당사자에게만 보인다. `/파티정보`만 정보성 명령으로서 공개 모드의 영향을 받는다.

채팅 입력창에서 주황색 `파티` 타입을 고르면 `partyManager.getParty()`가 반환한 현재 온라인 멤버들에게만 메시지를 남긴다. 서로 다른 채널·장소에서도 각 파티원의 현재 필터 히스토리로 전달되며 파티가 없으면 서버가 전송을 거절한다.

## 파티 전투 피드

솔로 플레이의 스킬 시전 문구·효과 피드백·공격/회피 결과는 기존처럼 본인과 직접 피격 플레이어에게만 보인다. 파티에 속하면 시전자 또는 직접 전투 당사자를 제외한 온라인 파티원에게도 같은 메시지와 notification을 전달한다. 추가 수신자의 채팅에는 `[파티]` 플래그를 붙이고 각자의 현재 채널에 필터 히스토리로 저장하므로 주변 일반 플레이어나 공개 채널에는 노출되지 않는다. 파티원이 다른 장소에 있어도 공유하며 파티 이탈·로그아웃 즉시 audience에서 제외된다.

## 몬스터 경험치 공유

몬스터의 드롭과 골드는 기존처럼 현재 위협 테이블의 주 기여 플레이어에게 지급하고, 해당 플레이어가 없을 때 마지막 피해의 `attackOwner`로 fallback한다. 이 소유권은 경험치 적격 판정과 분리한다.

경험치 참여자는 첫 공격 시 고정한 교전 claim에 포함되고, 처치 기여 원장에 양수의 기여도가 있으며, 처치 시점에 온라인·동일 장소·생존 상태인 플레이어로 한정한다. 따라서 교전 중 뒤늦게 파티에 합류한 플레이어, 기여도가 0인 파티원, 다른 장소의 파티원, 접속을 끊거나 사망·제압된 파티원은 인원수와 보상에서 모두 제외한다. 원장 전체에 양수 기여가 하나도 없을 때만 claim·온라인·장소·생존 검증을 통과한 마지막 공격 owner를 1인 보상 대상으로 fallback한다.

유효 참여자가 `n`명이면 정수 경험치 풀은 `floor(기준 경험치 × (1 + 0.2 × (n - 1)))`로 계산한다. 각 참여자의 정확한 몫은 전체 풀의 20%를 인원수로 균등 배분한 값과, 나머지 80%를 개인 기여도 비율로 배분한 값의 합이다.

```text
개인 몫 = 풀 × (0.2 / n + 0.8 × 개인 기여도 / 전체 기여도)
```

각 몫의 정수부를 먼저 배정하고 남은 경험치는 Hamilton 최대 나머지법으로 나눈다. 우선순위는 소수 나머지 내림차순, 전체 기여도 내림차순, `userId` 오름차순이다. 이로써 분배 정수의 합이 정확히 전체 풀과 일치한다.

정수 몫을 확정한 뒤, 유효 참여자 중 최고 레벨과 본인 레벨의 차이에 다음 감쇠를 적용한다.

| 최고 레벨과 차이 | 경험치 배율 | 추가 상한 |
| --- | ---: | ---: |
| 0~9 | 100% | 없음 |
| 10~19 | 50% | 없음 |
| 20~29 | 20% | 없음 |
| 30 이상 | 10% | 본인 다음 레벨 요구 경험치의 10% |

레벨 차이 감쇠와 상한 후에 장비·버프 등 본인의 경험치 획득 배율을 마지막으로 적용한다. 각 참여자는 실제 지급된 양과 레벨 차이 감쇠를 개인 보상 메시지로 확인한다. 지급된 처치 경험치는 다음 Player 사망 판정이 끝날 때까지만 사망 패널티 차감 대상에서 제외되어, 처치 직후 같은 월드 프레임에 사망한 참여자도 보상을 잃지 않는다. 그 판정이 지나면 남은 경험치는 다시 일반 경험치와 같은 규칙을 따른다.

## HUD

`PlayerStatsData.party`는 파티가 없으면 `null`, 있으면 파티원별 레벨·HP·MP·파티장·같은 장소 여부를 포함한다. `PartyHud`는 기본 표시되며 HUD 설정에서 위치·크기·투명도·표시 여부를 바꿀 수 있다. 다른 장소의 파티원은 흐리게 표시된다.
