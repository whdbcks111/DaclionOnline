# 전투 Pipeline·위협도·기여도

## 전투 Pipeline

`Entity.attack()`은 기존 회피·치명타·상성·방어/관통·보호막 계산의 단일 진입점이며, `CombatPipeline`이 계산 사이의 확장 지점을 제공한다.

회피율의 공격 측 속도는 `Entity.getEvasionAttackSpeed()`로 조회한다. 일반 Entity의 근접 공격은 이동속도를 사용하지만 Projectile은 발사자의 이동속도를 배제하고 최종 `projectileAcceleration`만 사용한다. 투사체 가속은 이동속도보다 작은 단위로 성장하므로 `1 + (가속 - 1) × 5`로 회피 판정 속도에 환산한다. 이에 따라 가속 +0.1배는 유효 적중 속도 +0.5가 되며 비행시간과 실제 적중률을 함께 개선한다. `unavoidable` 공격은 기존처럼 이 계산을 건너뛴다.

기술·무기·패턴은 `AttackOptions.combatMessage`에 선택적인 `title`과 `comment`를 전달할 수 있다. 기술명은 적중과 회피 기록에 모두 남고, comment는 단순 문자열 또는 tooltip·아이콘을 포함한 `ChatNode[]`를 받아 최종 피해 아래에 상황 설명을 삽입한다. 피해 계산을 우회해 별도 공격 메시지를 만들지 말고 이 옵션을 사용한다.

투사체가 아닌 직접 속성 기술은 `AttackOptions.effectTags`에 해당 기술의 `property:*` 태그를 전달한다. 이 태그는 해당 한 번의 상성 판정에만 사용되므로 시전자 본체나 장착 무기에 속성을 임시 부여하지 않는다. 생략하면 기존처럼 실제 공격 Entity 본체의 공격원 태그를 사용한다. 독을 바른 물리 칼날처럼 상태효과만 속성을 가진 기술은 직접 피해의 `effectTags`에서 독을 제외할 수 있다.

직접 공격의 방어구 내구도 손상은 보호막 흡수 뒤 실제 생명력 피해를 기준으로 한다. 기본 `ArmorDurabilityDamageMode.SINGLE`은 피해 비율에 따른 10~70% 확률로 몸통 40·다리 25·머리 20·발 15 가중치 중 장착된 한 부위만 손상시킨다. 넓은 범위의 파괴적 특수 공격만 `AttackOptions.armorDurabilityDamageMode = ALL`을 명시해 장착 중인 전 부위를 한 번씩 손상시킨다. 회피하거나 보호막이 피해를 모두 흡수하면 어느 모드도 내구도를 줄이지 않는다.

| 단계 | 용도 |
| --- | --- |
| `PREPARE` | 공격 가능 조건을 추가 검사하거나 `cancelled/cancelReason`으로 취소 |
| `EVADED` | 회피 결과 후 효과 |
| `BEFORE_DAMAGE` | 치명타 적용 후 실제 `damage()` 전 피해량·타입 보정 |
| `AFTER_DAMAGE` | 실제 생명력/보호막 피해가 확정된 뒤 흡혈·위협도·적중 효과 처리 |
| `COMPLETE` | 회피를 포함한 공격 수명 종료 |

```ts
const unregister = registerCombatHook({
  key: 'skill:berserk',
  stage: CombatStage.BEFORE_DAMAGE,
  filter: context => context.attackOwner === owner,
  run: context => { context.amount *= 1.2 },
})
```

hook은 key 재등록으로 교체되고 반환 함수 또는 `unregisterCombatHook`으로 해제한다. 낮은 `priority`부터 실행한다. 영속 상태나 무기 raw data를 hook에서 직접 읽지 않고 Entity/Equipment/SkillBook 공개 API를 사용한다. `GameEvent`는 확정된 사실의 통계·퀘스트 전달용이고 전투 수치를 바꾸는 용도로 사용하지 않는다.

### 방어·관통 계산

물리 방어력과 마법 저항력은 유효 방어 `e = max(0, 방어 - 관통)`와 `방어 적용 피해 = 원피해 × K / (K + e)`를 공유한다. 공격 source가 있으면 기준 레벨 `L`은 공격자의 최종 `attackOwner`와 피격자 중 낮은 레벨이며, 환경 피해처럼 source가 없을 때만 피격자 레벨을 사용한다. 따라서 고레벨 대상을 때린다는 이유만으로 저레벨 공격자의 동일 방어 관통 효율이 부풀지 않는다. 레벨 척도는 Lv.200까지 기존 `K(L) = 100 + 2L + 0.005L²`, 이후 `K(L) = 4L - 100`으로 연속 연결해 후반 이차 증가를 제거한다. 관통이 방어 이상이면 원피해를 유지하고 방어가 높아져도 피해가 갑자기 0이 되지 않으며, 공식 전체가 원피해에 비례하므로 치명타 배율도 그대로 유지된다.

공격 source가 있는 비고정 피해는 방어 계산 뒤 레벨 차이 배율 `M = clamp(0.5, 2, 2^((공격자 레벨 - 피격자 레벨) / 300))`을 적용한다. 동레벨은 정확히 1배, 300레벨 우위는 2배, 300레벨 열위는 0.5배이며 그 이상의 격차는 같은 상한·하한에 머문다. 상한에 닿기 전 정반대 레벨 차이는 서로 역수이므로 높은 레벨이 가하는 피해와 낮은 레벨이 받는 피해가 같은 규칙으로 커지고 줄어든다. 고정 피해, source 없는 환경 피해, 같은 최종 `attackOwner`의 자해는 1배를 유지한다. `Entity.calculateDefendedDamageFrom()`이 런타임 경계를 소유하고 `Balance.calculateProjectedCombatDamage()`가 같은 공개 API를 사용하므로 실제 전투와 밸런스 보고서가 같은 결과를 낸다.

기존 몬스터의 동레벨 피해 감소율은 새 척도로 바뀌어도 유지한다. `normalizeMonsterDefenseForScale()`가 Lv.200 초과 방어·마법 방어를 `D새 = D기존 × K새 / K기존`으로 변환하며, 공용 프로필 예산·최종 override와 레거시 authored 마스터 모두 등록 경계에서 같은 정규화를 거친다.

### 몬스터 생명력·공격 성장

표준 일반 몬스터의 최대 생명력은 `300 + 75L + 4L² + 0.002L³`으로 계산한다. 보스 체급은 `4.8 + 4.2 / (1 + (L/100)²)`, 필드 보스는 `4 + 2 / (1 + L/150)`를 생명력에 곱한다. 두 체급 배율은 고레벨에서 특정값으로 점근해 레벨을 여러 번 곱하던 기존 곡선의 폭증을 막고, Lv.1~1000 구간에서 필드 보스는 보스보다 낮은 생명력과 단조 성장을 유지한다.

일반·정예 몬스터의 공격 예산은 Lv.1/50/100/200/350/1000에서 5/38/90/175/185/400을 지나도록 선형 보간한다. 예산은 전 구간에서 감소하지 않으며 `MonsterStatProfile`, 고유 weight, 정예 체급 배율을 거쳐 공격력·마법력으로 배분된다. 필드 보스·보스는 별도 패턴과 파티 압력을 보존하기 위해 기존 `5 + 2L + 0.01L²` 공격 예산을 유지한다.

`defineWorldMonster()`는 명시 프로필 마스터의 전체 계산값과 최종 override를 기존처럼 적용한다. 수동 수치로 남은 레거시 마스터도 일반·정예라면 공격력·마법력과 최대 생명력을 저장된 `statProfile/statRank/statWeights`의 공용 계산값으로 통일하고, 방어·속도 같은 나머지 고유 성향은 보존한다. 보스의 기존 공격 수치와 패턴은 이 호환 변환 대상이 아니다.

`npm run balance:report -- pressure`는 추천 장비를 착용한 6개 1차 직업의 동레벨 일반 몬스터전 순 생명력 소모 p25·중앙값·p75와 예상 사망 수를 레벨별로 출력한다. 현재 66개 성장 프로필 전체 중앙값은 15~30%, p75는 50% 이하, 예상 사망은 최대 2개를 회귀 기준으로 삼는다. 지원 기술이 강한 직업과 공격형 직업의 실제 순 소모 차이는 억지로 같은 값으로 만들지 않는다.

전투 압력 분석은 평타·패턴 피해와 회복·보호막 시전을 하나의 시간축으로 재생한다. 같은 시각에는 피해를 먼저 적용하고, 회복은 최대 생명력까지만 인정하며, 보호막은 실제 지속시간에 만료되고 같은 스킬을 다시 쓰면 남은 양을 새 보호막으로 교체한다. 보고서의 `projectedSupportBeforeKill`에는 과잉 회복이나 만료된 보호막 생성량이 아니라 실제 회복량과 피해를 흡수한 보호막만 포함한다.

### 플레이어 전투 기술 템포

플레이어의 `skill:combat` 액티브는 성공 발동마다 0.9초의 전역 연계 간격을 시작한다. 이 간격은 개인·계열 공유 재사용 대기시간과 독립된 비영속 전투 상태이며, 평타·아이템·생활 기술과 몬스터/보스 런타임 SkillBook을 막지 않는다. 조건 실패나 시작 예외에는 생기지 않고 쿨다운 감소 효과로 줄일 수 없다. `Balance.analyzeCombatRotation()`도 같은 전역 `nextCombatSkillAt`을 사용하며 연계 대기 사이에는 평타를 계속 배치한다. 동레벨 회귀 기준은 일반 몬스터 처치 10초 이상, 보스 중앙값 120초 이상이고 느린 상한을 고정하지 않는다.

### 적응형 음악 교전 상태

`Entity.recordCombatEngagement()`는 Combat Pipeline의 `PREPARE`를 통과한 공격과 공격 source가 있는 실제 피해에서 양쪽 최종 `attackOwner`에게 교전을 알린다. 따라서 적중뿐 아니라 회피된 공격, 투사체와 source가 보존된 지속 피해도 포함하지만 취소된 공격·수동 대상 지정·광맥과 일반 오브젝트 공격은 포함하지 않는다. 서로 다른 장소의 owner도 교전으로 연결하지 않는다.

Player는 이 사실을 저장하지 않는 두 개의 9초 타이머로 유지한다. 일반 교전은 `combat`, 보스 교전은 우선순위가 높은 `boss`, 둘 다 만료되면 `exploration`이다. 일반 몬스터와 계속 싸워도 별도 보스 타이머가 연장되지 않아 9초 뒤 일반 전투 음악으로 내려가며, 장소 이동·사망·부활은 두 타이머를 즉시 지운다. 서버는 클래스형 `MusicCombatState`의 key만 `PlayerStatsData.musicCombatState`에 직렬화한다.

## 전투 제어 저항

상태효과의 hard/soft 제어 분류와 대상별 지속시간 상한·12초 연속 적용 점감은 `Entity.applyStatusEffect()`에서 최종 대상 기준으로 처리한다. 보스는 hard 제어가 최초에도 요청 시간의 35%, 최대 1.25초만 적용되고 같은 범주의 두 번째·세 번째 성공은 다시 50%·25%로 줄어든 뒤 네 번째부터 면역이 된다. 일반 몬스터와 플레이어도 각자 더 완만한 저항값을 사용하며 soft는 hard와 별도 기록을 사용한다. 이 규칙과 전체 분류표는 [상태효과 시스템](status-effects.md)을 참고한다.

## 몬스터 위협도

각 Monster는 자기 `ThreatTable`을 소유한다. 다른 기능은 테이블 Map을 읽지 않고 다음 API만 사용한다.

- `monster.recordThreat(actor, ThreatAction.*, amount)`
- `monster.engageIntruder(actor)`: 피해 전 보스방 감지처럼 최초 교전 위협을 한 번만 등록
- `monster.taunt(actor, power)`
- `monster.getThreatContributions()`
- `monster.getDefeatContributionSnapshot()`: 위협도 Entity와 분리된 userId 기반 처치 기여 원장 복사본
- `Entity.heal(amount, source)` / `setShield(..., source)`: 교전 중인 아군의 실제 생명력 회복량과 소스가 있는 보호막의 실제 피해 흡수량을 관련 몬스터에 자동 전파

`MonsterData.ai`는 다음 마스터 값을 가진다.

- `intelligence`: 0~100. 생략한 행동 가중치, 기본 도발 저항과 대상 고정 임계값의 기준.
- `disposition`: `LAST_ATTACKER`는 마지막 공격자만 추적하고, `THREAT`는 누적 점수를 비교한다.
- `weights`: 공격 시도, 실제 피해, 치유, 보호막, 제어, 도발의 단방향 위협 배율.
- `tauntResistance`: 도발 위협만 0~95% 감쇠한다.
- `switchThreshold`: 현재 대상보다 이 비율 이상 높은 후보가 생겨야 대상을 바꾼다.
- `decayPerSecond`: 전투 중 점수의 초당 감쇠율.

슬라임 계열은 지능 5의 `LAST_ATTACKER`로 마지막 공격자를 단순 추적한다. 수정맥의 군주는 지능 92의 `THREAT`로 치유 위협을 피해보다 높게 평가하고 도발 위협을 78% 감쇠하므로 힐러를 판단하면서 단순 도발에는 잘 넘어가지 않는다.

`location:boss_room` 마스터 태그가 붙은 전용 전투 공간은 `Location.update()`에서 같은 장소의 접속 중인 생존 플레이어를 살아 있는 보스의 위협도 테이블에 최초 한 번 등록한다. 따라서 플레이어가 보스를 직접 때리지 않아도 보스가 먼저 공격하며, 알집·공명 수정·거울·고정자처럼 보스 보호 기믹을 먼저 공격해도 전투를 피한 채 보조 오브젝트만 제거할 수 없다. 적갈기 늑대왕·모래전갈 여왕·서리거미 여왕·안개 세이렌처럼 명시적으로 야외 필드 보스인 장소에는 이 태그를 붙이지 않아 기존 피격 반응형 AI를 유지한다.

몬스터가 플레이어의 첫 공격 시도를 받으면 그 플레이어와 당시 파티원 userId를 교전 선점 snapshot으로 고정한다. 선점 밖 플레이어의 공격·도발·지원 위협은 거절되므로 비파티 처치 가로채기가 불가능하다. 선점 구성원이 모두 사망하거나 장소를 벗어나 ThreatTable에서 제거되면 선점도 해제되어 다른 플레이어나 파티가 새로 교전할 수 있다. 보스방 입장 감지는 선점을 만들지 않으며 실제로 먼저 공격한 쪽이 선점한다.

초반 보스도 성향을 분리한다. 적갈기 늑대왕은 지능 28로 피해와 마지막 공격에 비교적 잘 반응하며, 은빛그물 거미여왕은 지능 72로 치유·제어 행동을 더 큰 위협으로 평가하고 도발 위협을 52% 감쇠한다.

## 보스 조우 연출과 대사

모든 `entity:boss` 마스터는 고유 설명과 주 속성 콘셉트로 만든 `bossNarrative`를 가진다. 보스방 입장 선공 또는 야외 보스에 대한 첫 공격으로 교전이 시작되면 같은 장소 플레이어에게 보스 설명과 도입 대사를 남기고 3초 동안 받는 피해 배율을 0으로 만든다. 이 시간에는 보스의 일반 공격·스킬·미니게임 AI도 정지한다. 도입 종료 메시지 뒤 무적이 해제되며 생명력 70%와 35% 이하에서 각 전투당 한 번씩 단계 대사를 출력한다.

피해를 입은 보스가 유효한 전투 대상을 모두 잃으면 10초의 이탈 유예 시간을 센다. 그동안 새 대상이 생기지 않으면 최대 생명력의 10%를 초당 회복하며, 새 교전이 시작되면 유예와 회복을 즉시 중단한다. 프레임 길이가 달라도 지연을 초과한 시간만 회복량에 반영한다.

도입 중 현재 대상이 사망하거나 장소를 떠나도 같은 장소에 유효한 위협 대상이 남아 있으면 그 대상에게 남은 도입 시간과 무적을 그대로 이어간다. 모든 대상이 사라진 경우에만 무적과 대사 상태를 즉시 정리한다. 전투 중 이탈도 유효한 대체 대상이 없을 때 진행 중인 SkillBook 캐스팅을 `CANCELLED`로 끝내고 스킬 순서·첫 패턴 대기·도입·미니게임을 모두 초기화한다. 재진입은 도입 3초와 첫 패턴 대기부터 새로 시작하므로 이탈 전에 예고한 공격이 즉시 이어지지 않는다. 사망·리스폰·교전 해제도 같은 초기화 경계를 사용하므로 다음 파티의 전투에 이전 단계가 남지 않는다. 대사는 위치의 온라인 사용자 ID snapshot에만 전송하며 전투 수치나 위협도는 변경하지 않는다.

벨카인의 무관성주 테오른은 지능 92의 위협형이지만 공허창과 성벽 파단을 고정 순서로 사용한다. 공허섭정 라시엘은 지능 100, 도발 저항 98%로 치유·보호막·제어를 피해보다 크게 평가하고 세 판결 기술을 무작위로 사용한다. 왕관 기둥이 남아 있는 동안 받는 피해가 40%만 적용되므로 파티는 위협 대상 교대와 별개로 기둥 파괴를 먼저 수행해야 한다.

루나리스 해구의 월조 리바이어던은 지능 72의 위협형으로 해일과 수압 분쇄를 고정 순서로 사용한다. 백야대사제 세르미아는 지능 100, 도발 저항 99%로 치유·보호막·제어 위협을 피해보다 크게 평가하고 백야·월식 기술을 무작위로 사용한다. 조류거울이 남아 있는 동안 받는 피해가 35%만 적용되므로 파티는 거울을 먼저 파괴해야 한다.

카미하라 숲의 역근 포식수는 고정 순서로 낙하와 포자 숨결을 사용한다. 에오나의 심장 아르보르는 지능 100, 도발 저항 99.5%로 치유·보호막·제어 기여를 피해보다 크게 평가하고 세 기술을 무작위로 사용한다. 심장씨앗이 하나라도 남으면 받는 피해가 30%만 적용되므로 파티는 씨앗부터 파괴해야 한다.

철근 심장수호자는 누적 위협으로 고른 현재 대상 한 명에게 `철근 압살`을 사용한다. 이 공격은 후반 엘리트의 높은 이동속도와 방어 능력치에 0 피해가 되지 않도록 `Entity.attack()`의 `unavoidable + fixedDamage` 옵션을 명시해 보호막은 정상 소모하되 회피·속성·방어 계산을 건너뛰고, 적중 후 3초 제압을 확정 적용한다. 공명 폭주 실패 피해도 같은 고정 피해 경계를 사용한다.

## 고레벨 역할 파훼

Lv.420·460·500의 세 왕좌 보스는 `bossRoleBreakConfig.ts`의 단일 설정을 마스터 배치, 판정, 전투 안내와 테스트가 함께 사용한다. challenge가 시작되면 보스가 받는 피해를 줄이는 ward가 생기며, 시작 뒤 새로 발행된 `STATUS_EFFECT_APPLIED/UPDATED`와 유효한 `MONSTER_TAUNTED`만 조건으로 인정한다. 이미 걸려 있던 약화는 소급하지 않는다.

| 보스 | 제한시간 | 시작 후 역할 조건 | 진행 중 받는 피해 | 성공 노출 | 실패 고정 피해 |
| --- | ---: | --- | ---: | ---: | ---: |
| 성운제 아스테리온 | 12초 | 방어력 감소 + 마법 저항력 감소 | 55% | 7초간 115% | 최대 생명력 28% |
| 영시여왕 크로니아 | 11초 | 도발 + 마법 저항력 감소 | 50% | 7초간 118% | 최대 생명력 35% |
| 최후성좌 라스트라 | 14초 | 도발 + 방어력 감소 + 마법 저항력 감소 | 45% | 8초간 120% | 최대 생명력 42% |

`MonsterChallengeHandle.update(dt)`는 challenge가 활성화된 동안 보스 AI 대신 매 게임 tick 호출된다. 성공 뒤에도 노출 시간이 끝날 때까지 challenge를 유지하므로 공격·스킬은 멈추고 파티가 짧은 집중 공격 시간을 얻는다. 벽시계 timer는 쓰지 않으며 이탈·사망·리스폰·취소에서 이벤트 구독과 ward/노출 modifier를 함께 정리한다. 기존 미니게임 handler는 `update`를 생략해 같은 수명주기를 유지한다.

시간 초과 피해 대상은 파티 명단이 아니라 보스의 양수 처치 기여 userId snapshot으로 고르고, 기여가 없는 현재 대상만 fallback으로 더한다. 플레이어 registry에서 같은 장소·생존 상태를 다시 확인하므로 교전 claim에만 들어온 무기여 부계정, 이탈자와 사망자는 제외된다. 피해는 방어를 무시하는 실제 `Entity.damage(..., fixedDamage: true)`를 사용하지만 28~42% 비율이라 즉사·강제 reset 없이 솔로도 피해를 감수하고 전투를 이어갈 수 있다.

## 몬스터 기술 기록

몬스터가 시전 시간이 있는 기술을 시작하면 같은 장소의 온라인 플레이어에게 기존 실시간 notification과 함께 `[ 전투 예고 ] 몬스터 · 기술명 (시전 시간)` 봇 메시지를 남긴다. 예고에는 회피 불가 여부와 예정된 상태이상·지속시간처럼 플레이어가 대응에 필요한 가공 정보만 표시한다.

공격이 끝나면 `AttackOptions.combatMessage`를 통해 기술명과 전투 코멘트가 피해 또는 회피 기록에 남는다. 예를 들어 공허한 해골왕의 `백골 왕명`은 왕관의 명령이 의지를 짓누른다는 문구와 공포 레벨·지속시간을 함께 보여준다. 회복처럼 `Entity.attack()`을 거치지 않는 보스 기술은 같은 장소 사용자에게 실제 회복량을 별도 결과 기록으로 전송한다.

## 기여도와 보상

위협도와 처치 기여도는 서로 다른 수명을 가진다. 대상 선정용 위협도 테이블은 시간에 따라 감쇠하고 사망·이탈한 Entity를 제거한다. 보상용 기여 원장은 userId와 확정된 수치만 소유하며 처치·리스폰 reset 전까지 별도로 보존한다. 몬스터는 사망 처리의 이벤트·일회성 제거·reset이 실행되기 전에 교전 claim과 원장을 Entity 참조 없는 불변 snapshot으로 복사한다.

기여도는 다음 실제 전투 결과만 한 번씩 누적한다.

- 피해: 직접 공격과 실행 중 source가 보존된 지속 피해는 `Entity.damage()`의 확정 결과인 `lifeDamage + absorbedDamage`를 최종 공격 owner에게 한 번 기록한다. 영속 복원으로 raw source가 사라진 지속 피해는 서버가 보존한 `DamageCause.actorPlayerId`로 실제 양수 `lifeDamage`만 primitive 원장에 기록하고 AI 공격 대상으로 되살리지 않는다. 최대 생명력을 넘는 overkill은 실제 생명력 감소분에 포함하지 않는다.
- 치유: 대상의 손실 생명력을 실제로 복구한 `healedAmount`만 source owner에게 기록한다.
- 보호막: 생성한 양이 아니라 source가 보존된 보호막이 실제 피해를 흡수한 양만 source owner에게 기록한다.
- 제어: 대상별 저항·지속시간 상한·연속 적용 점감을 모두 거친 실제 가동 시간에 `몬스터 최대 생명력 × 1% × 실제 가동 초`를 적용한다.

모든 기여 기록은 첫 공격 시점의 교전 claim과 몬스터 위치를 통과해야 한다. `Entity.damage()`는 마지막으로 시도된 피해 원인과 별도로 실제 `lifeDamage > 0`으로 생명력을 0으로 만든 `lastLethalDamageCause`를 보존한다. 이 원인의 `actorPlayerId`는 직접 Entity를 우선해 서버가 정규화하며, 보호막에 전부 흡수되거나 이미 생명력 0인 후속 피해는 막타를 덮어쓰지 않는다. 경험치는 우선 snapshot에 포함된 claim 인원 중 양수 기여·온라인·동일 장소·생존 조건을 모두 만족한 플레이어에게 지급한다. 이 현장 대상이 한 명도 없고 독·출혈 같은 서버 지속 피해의 실제 막타자가 온라인·생존 상태라면, 장소를 이동했더라도 그 한 명에게 기준 솔로 경험치 풀을 지급한다. 현장 기여자가 있으면 원격 막타자를 추가하지 않아 경험치 풀과 개인 지급을 중복 생성하지 않는다. 실제 막타 정보가 없는 구형·환경 경로에서만 양수 원장 자체가 빈 경우 claim 검증을 통과한 마지막 공격 owner로 fallback한다. 유효 인원수에 따라 늘린 전체 경험치 풀은 20% 균등 몫과 80% 기여 몫으로 Hamilton 정수 배분한 뒤 레벨 차이 감쇠와 개인 경험치 배율을 순서대로 적용한다. 세부 공식과 동률 규칙은 [파티 시스템](party.md)을 따른다.

드롭·골드 소유자는 기존처럼 현재 위협 테이블의 주 기여 플레이어, 기록이 없으면 마지막 피해 owner로 정하여 경험치 적격성과 분리한다. 처치 경험치는 Location/Projectile 갱신 뒤 다음 Player 사망 판정까지 획득분만 별도로 추적하므로, 처치와 사망이 같은 월드 프레임에 확정되어도 뒤늦은 사망 패널티가 보상을 소급해 차감하지 않는다. 처치·리스폰 시 위협과 보상 원장을 함께 초기화한다.
